# Growse v0.6.0 スコープ定義書

## 1. 文書概要

本書は、Growse v0.6.0で実装するCSS Grid Layoutと高度なPaint・Compositingの範囲、完了条件、および対象外を定義する。

v0.6.0は、v0.4.0のCSS3 Coreとv0.5.0のFlexboxが完成していることを前提とする。

---

## 2. リリーステーマ

> **二次元レイアウトと重なりを扱い、Webアプリケーションらしい画面を描けるブラウザへ。**

GridのTrack SizingとItem PlacementをLayout Engineへ導入し、Positioned Layout、Stacking Context、Transform、ShadowなどをDisplay ListとRendererへ接続する。

---

## 3. 準拠基準

本書で明示した範囲について、次を基準とする。

- CSS Grid Layout Module Level 1
- CSS Box Alignment Module Level 3
- CSS Positioned Layout Module Level 3
- CSS Transforms Module Level 1
- CSS Backgrounds and Borders Module Level 3
- CSS Color Module Level 4のうちGradientとalpha合成に必要な範囲
- Compositing and Blending Level 1のうち通常alpha compositing

Subgridを含むGrid Level 2全体への適合は宣言しない。

---

## 4. 目標

1. explicit / implicit Gridを生成する
2. fixed、percentage、flexible、intrinsic Track Sizeを解決する
3. line、span、area、およびauto-placementでItemを配置する
4. GridとFlexを相互にnestできる
5. Positioned Layoutとz-indexを導入する
6. Stacking Contextに基づくPaint順とHit Testingを実装する
7. Shadow、複数Background、Gradient、Transform、Clip、Opacityを合成する
8. Dynamic DOM、hover、resize、scroll後もgeometryと描画を一致させる

## 6. Grid Layout Algorithm

次を独立した段階として実装する。

1. explicit Gridの構築
2. definite positionを持つItemの配置
3. locked axisを持つItemの配置
4. auto-placement cursorによる残りのItem配置
5. implicit Trackの生成
6. available spaceとTrack sizing functionの初期化
7. intrinsic track sizeの解決
8. flexible trackの`fr`分配
9. stretched auto trackの調整
10. Grid containerのcontent-based minimum size決定
11. item alignmentとauto margin
12. 最終Box geometryの生成

`grid-auto-flow: dense`はDOM順を変更せず、空き領域への視覚的な後詰めだけを行う。

---

## 7. Positioned Layout

### 7.1 Position

- `position: static | relative | absolute | fixed | sticky`
- `top` / `right` / `bottom` / `left`
- `inset`、`inset-block`、`inset-inline`と各Longhand
- `z-index: auto | <integer>`

Containing BlockをLayout Treeに明示し、absolute childを通常Flowから除外する。fixedはViewport、stickyは最寄りのScroll Containerを基準とする。

### 7.2 Stacking Context

少なくとも次でStacking Contextを生成する。

- root element
- positioned elementと非auto z-index
- opacityが1未満の要素
- transformがnone以外の要素

Paint順、Clipping、Opacity、Transform、Hit Testingは同じStacking Treeを参照する。

### 8.1 BackgroundとBorder

- 複数Background Layer
- `linear-gradient()` / `radial-gradient()`
- repeat、position、size、origin、clip
- border radiusの独立した各角
- `box-shadow`
- `text-shadow`

### 8.2 Transform

- `transform: none`
- translate / translateX / translateY
- scale / scaleX / scaleY
- rotate
- skew / skewX / skewY
- matrix
- 複数Transform Function

### 8.3 Compositing

- group opacity
- source-over alpha compositing
- nested clip
- stacking context単位のoffscreen layer

Blend Mode、Filter、Backdrop Filterは対象外とする。

---

## 9. Hit Testing、Scroll、Interaction

- Hit Testingは逆Paint順で最前面の可視Boxを選択する
- Transformの逆行列でPointer座標をlocal coordinateへ変換する
- border radiusとclip外の領域を対象にしない
- opacity 0でも仕様上Pointer対象となる状態を維持する
- `display:none`とvisibility hiddenを区別する
- absolute、fixed、sticky要素の最終表示位置を使う
- Grid itemの重なりではStacking Contextとz-indexを使う
- scroll後もfixed、sticky、transformed elementの対象が一致する
- hoverによるTrack、Position、Transform変更は次のFrameで再評価する

---

## 10. Performance

- Grid Track計算をLayout Pass内の明示的なWork Unitとして計測する
- viewport resize時に影響のないStyle Parseを再実行しない
- Paint-only変更では可能な限りLayoutを再実行しない
- TransformとOpacityだけの変更をDisplay List更新へ限定できる構造にする
- Layout、Paint、Hit Test用Tree間でNodeIDとGeometryの複製ルールを定義する
- pathologicalなrepeat、巨大Grid、深いStacking Contextへ上限または安全策を設ける

性能目標は固定FPSだけで判定せず、代表Demoに対するLayout・Paint時間とAllocationを継続計測する。

- Grid shorthandとtrack list parsing

- intrinsic / flexible track sizing
- alignment、auto margin、gap

### 11.2 Integration Test

- fixed + fr + intrinsic trackの混在
- row/column spanとimplicit Grid
- nested Grid、Grid in Flex、Flex in Grid
- viewport resizeとauto-fill / auto-fit
- absolute/fixed/sticky item
- z-index、opacity、transformが混在するHit Testing
- scroll後のfixed/sticky/transform
- WebGoによるGrid item追加・削除・class変更
- hoverによるTrackとTransform変更

### 11.3 Visual Regression

決定的なFont、Viewport、Scaleを使用したReference Image Testを導入する。pixel差分だけでなく、Layout geometry、Display List、Hit Test順も同時に保存し、原因を切り分けられるようにする。

### 11.4 Conformance Test

Grid、Position、TransformのWeb Platform Testsから対応Featureに必要なTestを選定し、出典と未対応理由をCSS対応表へ記録する。
