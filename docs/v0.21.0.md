# Growse v0.21.0 スコープ定義書

## 1. 文書概要

本書は、Growse v0.21.0で実装する **Browser Search Suite** の範囲、完了条件、対象外を定義する。本書をv0.21.0の唯一の進捗台帳とし、実装、Test、Showcase、文書、CIが揃うまで完了checkboxを更新しない。

v0.21.0は、v0.20.0までの複数Tab、線形Session History、Browser chrome、URL入力、Navigation、DOM / Layout / Paint、focus、keyboard input、JavaScript Runtime、DevTools、安全なresource loadingが完成していることを前提とする。

既存のaddress barはURL入力とNavigation開始だけを提供しており、検索語判定、候補、検索provider、ページ内検索、Tab / History / Bookmark横断検索を持たない。v0.21.0ではaddress barをOmniboxへ発展させ、入力開始から候補選択、検索結果Navigation、ページ内探索、過去の情報への再到達までを一貫した検索体験にする。新しいTabには、Growseのロゴ、中央検索欄、サイトshortcut、背景を備えた内部の検索ホーム画面を提供する。

---

## 2. リリーステーマ

> **検索ホームとOmniboxから、URLと検索語を意識して使い分けなくても、Web、ページ内、開いているTab、閲覧履歴、Bookmarkを高速かつ安全に探せる現代的なBrowser Search Suiteを確立する。**

利用者はOmniboxへ自然な語句を入力し、keyboard、mouse、IMEのいずれでも候補を選択できる。検索先、外部suggestionへの送信、履歴保存を自分で制御でき、検索失敗やnetwork遅延が現在のPageや入力内容を壊さない。

---

## 3. 準拠基準

- WHATWG URL StandardのURL parse、host、IDNA、percent-encodeに関する選定範囲
- HTML Living Standardのfocus、editing、keyboard event、Session Historyに関する選定範囲
- OpenSearch 1.1の検索URL templateとdescription documentの選定範囲
- WAI-ARIA Authoring Practicesのeditable combobox、listbox、dialog patternの選定範囲
- WCAG 2.2のKeyboard、Focus Visible、Focus Order、Name / Role / Valueに関する選定達成基準
- Unicode Standard Annex #15のNormalizationと、Unicode case foldingの検索に必要な選定範囲

仕様全体への適合や他Browserとのranking完全一致は宣言せず、本書に明示した入力、候補source、provider、検索mode、shortcut、安全上限に限定する。

---

## 4. 目標

1. URL、検索語、Omnibox commandを決定的に分類し、誤送信や意図しないNavigationを防ぐ
2. Web suggestion、開いているTab、閲覧履歴、Bookmarkを一つの候補UIへ統合する
3. 検索providerを安全に追加・変更でき、外部suggestionへのquery送信を利用者が制御できる
4. Page本文を変更せず、件数、現在位置、highlight、次・前移動を備えたページ内検索を提供する
5. IME composition、keyboard only、mouse、narrow viewport、複数Tab、遅延応答でも入力とfocusを失わない
6. 検索index、remote response、highlight、diagnosticへ有限な上限とcancel可能なLifecycleを設ける
7. 新しいTabの検索ホームから、中央検索欄とサイトshortcutで検索・Navigationを始め、背景とshortcutを自分で設定できる

## 5. Smart Omnibox

### 5.1 入力分類

Omnibox submit時に、前後の空白を除いた入力をURL、検索query、Omnibox commandのいずれかへ分類する。明示した`http://` / `https://`、`localhost`、IPv4 / IPv6、妥当なdot付きhostと任意portはURLとして扱う。それ以外の自然言語、空白を含む文字列、CJK、emojiは検索queryとして既定providerへ渡す。

schemeらしいprefix、credentialを含むURL、壊れたport、制御文字、上限超過は検索へfallbackせず、入力を保持した可視errorにする。単一labelのintranet hostは`http://`または`https://`の明示を必要とし、利用者の入力を外部providerへ誤送信しない。

### 5.2 編集とNavigation

focus時の全選択、caret移動、範囲選択、copy / cut / paste、undo / redo、IME compositionを維持する。`Enter`は選択中候補、`Shift+Enter`は入力を新規Tab、`Alt+Enter`は検索結果をbackground Tabで開く。候補未選択時は現在の入力を分類して実行する。

Navigation開始後もoperationを開始したTabへ結果をpinし、別Tabへの切替、連続submit、cancel、失敗でactive TabのOmniboxを上書きしない。表示URL、編集中text、committed URLを別stateとして管理する。

### 5.3 Omnibox command

`@tabs`、`@history`、`@bookmarks`、`@search`を予約scopeとして提供する。scope名の後ろにqueryを続けるとsourceを限定し、queryが空なら最近順の候補を表示する。通常のWeb query内に現れる`@`はcommandとして誤解釈しない。

## 6. Suggestion Pipeline and Ranking

### 6.1 候補source

候補は入力そのものの検索 / URL action、開いているTab、閲覧履歴、Bookmark、選択providerのremote suggestionから生成する。各候補はsource icon / label、primary text、補助text、実行actionを持ち、同じ正規化URLは一件へ統合する。

local候補は入力のたびに即時生成し、remote suggestionはdebounce後に別generationとして取得する。新しい入力、Tab切替、popup close、provider変更、window closeで古いrequestをcancelし、遅れて到着したresponseを現在の候補へ混ぜない。

### 6.2 Ranking

rankingは完全一致、prefix一致、word boundary一致、substring一致の順を基本とし、open Tab、Bookmark、typed history、通常history、remote suggestionのsource weight、recency、visit countを加味する。scoreとtie-breakは決定的にし、同じ入力とsnapshotから同じ順序を返す。

URL fragment、default port、host case、末尾slashを正規化して重複を除くが、異なるorigin、path、queryを誤って統合しない。queryとtitleはUnicode normalizationとcase foldingを行い、日本語は空白分割を前提にせずsubstringで検索できる。

### 6.3 Popup interaction

候補popupは最大12件を表示し、`ArrowUp` / `ArrowDown`、`PageUp` / `PageDown`、`Home` / `End`、`Enter`、`Escape`、`Tab`で操作できる。選択候補はOmnibox textのpreviewに使うが、確定前の入力を破棄しない。mouse hoverとkeyboard selectionを同期し、popup外clickとfocus移動で安全に閉じる。

---

## 7. Search Provider

### 7.1 Provider model

providerは一意なID、表示名、keyword、HTTPS検索URL template、任意のHTTPS suggestion endpointを持つ。検索templateは一個の`{searchTerms}`を必須とし、UTF-8 queryを一度だけpercent-encodeする。初期providerはDuckDuckGoとし、設定画面から既定providerを変更できる。

利用者はcustom providerを追加、編集、削除できる。built-in providerは削除不能だが無効化できる。keywordをOmnibox先頭へ入力すると、既定を変更せず一回だけproviderを切り替えられる。

### 7.2 Discovery and validation

Pageが宣言するOpenSearch descriptionを候補として検出するが、自動登録しない。利用者の確認後にのみ登録し、descriptionとtemplateを同一のnetwork / redirect / size policyで検証する。

検索とsuggestion endpointはHTTPSを必須とし、credential、fragment、script scheme、unknown placeholder、過剰なredirectを拒否する。localhostのoffline Showcaseだけは明示したtest providerを許可する。

### 7.3 Privacy control

remote suggestionは既定で無効とする。有効化時は送信先provider、送信される入力、無効化方法を設定画面に表示する。空入力、Omnibox command、URL / credentialらしい入力、private IP / localhost、制御文字を含む入力はremote endpointへ送らない。

provider変更とremote suggestion設定はprofileへ保存し、破損した設定は安全なdefaultへ復旧する。query、suggestion response、閲覧履歴をapplication logやcrash messageへ複製しない。

---

## 8. Search Data and Local Index

### 8.1 Browsing History

成功したtop-level NavigationをURL、title、last visited、visit count、typed countと共にprofileへ保存する。reload、same-document fragment移動、redirect chainの中間URL、失敗Navigationは重複entryを作らない。個別削除、期間指定削除、全削除を提供し、削除したentryを候補やindexへ残さない。

### 8.2 Bookmark

現在のPageをtoolbar actionまたはshortcutでBookmarkへ追加し、title、URL、作成日時を編集できる。重複URLは既存entryを更新し、削除は即時に候補へ反映する。v0.21.0ではfolderとtagを持たないflat collectionに限定する。

### 8.3 Index and persistence

History / Bookmarkの検索indexはprofile dataから再構築可能な派生dataとする。書込みはtemporary file、sync、atomic renameでcommitし、中断や破損時に直前の有効snapshotまたは空indexへ復旧する。複数windowの同時writerはlockまたはsingle-writer brokerで直列化する。

indexはURL、host、titleの正規化tokenとsubstring検索を支え、query本文やPage本文は保存しない。検索はUI threadを長時間blockせず、cancelとgeneration checkを通じてstale resultを破棄する。

## 9. Find in Page

### 9.1 Match semantics

`Ctrl+F` / `Cmd+F`でactive Tab専用のfind barを開き、可視text nodeをDOM順に検索する。既定はUnicode normalization済みのcase-insensitive substring一致とし、case sensitive、whole wordを切替可能にする。CJKは文字列単位で一致し、combining sequenceを途中で分断しない。

`Enter` / `F3`は次、`Shift+Enter` / `Shift+F3`は前へ循環し、現在位置と総件数を表示する。zero match、空query、上限超過、検索中を区別する。`Escape`はbarとhighlightを閉じ、Pageのscroll / focusを検索開始前の状態へ戻せる。

### 9.2 Highlight and scrolling

全matchを非active highlight、現在matchをactive highlightとしてpaintし、DOM textやselectionを変更しない。matchがnested scroll container内にある場合は必要最小限scrollしてviewportへ入れ、sticky / fixed contentやBrowser chromeの下へ隠さない。

DOM mutation、font completion、layout、viewport resize後は同じqueryからrangeとgeometryを再構築し、削除済みnodeや古いfragmentを参照しない。Tab切替時はTabごとのquery、option、current match、scrollを分離する。

### 9.3 Text scope

`display: none`、`visibility: hidden`、hidden attribute、script / style、折り畳まれた非表示内容は対象外とする。pseudo-element / generated content、form control value、shadow tree、canvas、image内text、PDFはv0.21.0のページ内検索対象外とする。

---

## 10. Tabs, History, and Bookmark Search

### 10.1 Search surface

`Ctrl+Shift+A` / `Cmd+Shift+A`でSearch panelを開き、Tabs、History、Bookmarks、Allを切り替えられる。Omniboxの`@tabs` / `@history` / `@bookmarks`と同じquery engineとsnapshotを使用し、異なるranking結果を作らない。

Tab候補を実行すると既存Tabへ切り替え、重複Tabを開かない。History候補は現在または新規TabへNavigationし、Bookmark候補も同じopen dispositionを選べる。閉じたTabの復元、Tab group検索、他deviceとの同期は対象外とする。

### 10.2 Management

History / Bookmark panelではkeyboardとmouseで複数選択せず一件ずつ削除できる。全History削除は対象件数と影響を確認し、実行後にundoしない。active Tabや現在PageはHistory削除だけでは閉じない。

## 11. Search Home and New Tab

### 11.1 内部ホーム画面

初期の空Tab、新規Tabボタン、`Ctrl+T` / `Cmd+T`で作る空Tabへ、Growseの検索ホームを表示する。toolbarにHome actionを設け、現在Tabから同じ画面へ戻れる。Web URLを指定して開く新規Tabは、そのNavigation先を優先する。

画面はGrowseのロゴ、中央の検索欄、既定provider名、検索action、最大10件のサイトshortcut、背景変更actionで構成する。中央検索欄は空のホームを開いた際にfocusし、`Ctrl+L` / `Cmd+L`ではOmniboxへfocusを移す。ホームはnetworkなしで表示できる同梱の内部viewとし、外部Web PageやGoogleのサイトを読み込んで代用しない。

ホームの表示状態をWeb URL、Page DOM、Runtimeから分離し、各Tabで保持する。ホームとWeb Pageの間を移動した後も、戻る / 進むで対応するviewを復元できる。外部Pageのscriptやresource requestからホーム設定の読書きや内部UI actionを実行できない。

### 11.2 共通の検索と候補

中央検索欄はOmniboxと同じ入力分類、provider選択、scope command、query engine、snapshot、URL normalization、deduplication、rankingを使用する。同じ入力とsnapshotに対して、ホーム専用の候補順序や別の検索URL生成規則を作らない。既定providerを変更すると、表示名と検索先へ同じ設定を反映する。

`Enter`は選択候補または入力を現在Tabで実行し、`Shift+Enter`は入力を新規foreground Tab、`Alt+Enter`は検索結果をbackground Tabで開く。Tab候補は既存Tabへ切り替える。候補popupの最大12件、preview、keyboard / mouse操作、IME composition、入力保持、privacy filterはOmniboxと共通にする。

query、selection、previewはTabごとに分離する。ホームを離れる、Tabを切り替える、popupを閉じる、providerを変更する、Tab / windowを閉じる際はrequestをcancelし、古いgenerationの結果を破棄する。Navigation開始・完了やURLの自動更新で候補を再表示しない。失敗Navigationでは入力とerror表示を保持し、再試行できる。

### 11.3 Shortcutと背景設定

shortcutは利用者が固定したURLのflat collectionとし、追加、title / URL編集、削除、並び順変更を提供する。title、host、起動actionを判別できるtileで表示し、iconがない場合は同梱iconまたは文字のfallbackを使用する。ホームを表示するだけでは、shortcut先のPage、favicon、previewをnetworkから取得しない。

shortcut URLはNavigationと同じHTTP(S)、credential、port、入力上限の検証を通し、検索語やscript schemeを保存しない。同じ正規化URLは一件へまとめ、上限超過は既存設定と編集中の値を保持した可視errorにする。History / Bookmarkとは別の固定一覧として管理し、履歴を削除しても利用者が固定したshortcutを自動削除しない。

背景は単色と最大4種類の同梱presetから選択する。背景上でも検索欄、tile、text、focus indicatorを読めるsurfaceを保ち、desktop / narrowで中央検索欄とshortcut gridをviewport内へ配置する。

shortcutの内容・順序と背景選択はprofileへatomicに保存し、再起動で復元する。破損・write失敗・複数windowでの変更は既存のprofile保存policyに従い、直前の有効設定または同梱defaultへ復旧する。入力query、候補response、Page本文はホーム設定へ保存しない。

### 11.4 上限と対象外

shortcutは最大10件、titleは128 Unicode scalar value、URLは4,096 UTF-8 bytes、serializedホーム設定は64 KiBを上限とし、profile容量の上限へ算入する。検索欄と候補には既存のquery、source、merge、表示、remote timeoutの上限をそのまま適用する。

外部背景URL、画像アップロード、背景動画、履歴からの自動shortcut生成、Google account連携、Doodle、feed / widgetはv0.21.0のホーム対象外とする。AI回答、音声検索、画像検索は本書の既存の非対象に従う。

## 12. IME, Accessibility, and Responsive UI

IME composition中の`Enter`、矢印、Escapeを候補実行へ流用せず、composition確定後にだけquery generationを進める。Latin、CJK、emoji、combining mark、RTL textを入力してもcaret、selection、popup位置を壊さない。

Omnibox、suggestion popup、検索ホームの中央検索欄・shortcut・背景設定、Home action、find bar、Search panel、provider setting、Bookmark actionへ一意なaccessible name、role、state、focus orderを与える。keyboard onlyで全主要操作へ到達でき、focus indicatorを常時可視にする。animationはreduced motion設定に従う。

desktopとnarrow viewportでpopup / panelをviewport内へ収め、候補のprimary textを優先しつつsourceと補助textを判別可能にする。長いURLやtitleは一行省略し、選択項目のactionとoriginを隠さない。

## 13. Safety, Limits, and Failure Policy

- Omnibox入力は4,096 UTF-8 bytes、providerへ送るqueryは2,048 UTF-8 bytesを上限とする
- 候補生成はsourceごとに最大50件、merge後最大100件、表示最大12件とする
- ホームshortcutは最大10件、titleは128 Unicode scalar value、URLは4,096 UTF-8 bytes、ホーム設定は64 KiB、同梱背景presetは最大4種類とする
- Historyは最大50,000 entry、Bookmarkは最大10,000 entry、indexとmetadataのprofile使用量は合計64 MiBを上限とする
- remote suggestionは150 ms以上debounceし、同時requestはactive generationの1件、timeout 2秒、redirect最大3回、response最大256 KiBとする
- OpenSearch descriptionは最大64 KiB、providerは最大32件、keywordは32 Unicode scalar valueまでとする
- Find in Pageは最大10,000 match、検索対象textは16 MiB、1 frameの同期処理は8 msを目安に分割する
- 上限超過、parse失敗、network error、cancel、index破損はpanic、hang、silent fallbackにせず、入力を保持して有限な状態を表示する
- remote suggestion failureはlocal候補とNavigationを妨げず、provider responseのHTML、script、imageを実行・描画しない
- query、History、Bookmark、Page textをtelemetryへ送信しない。v0.21.0ではtelemetry自体を導入しない

## 14. テスト方針

- Unit Test: 入力分類、URL normalization、provider template、Unicode matching、deduplication、ranking、limit、serializationをtable-drivenで固定する
- Integration Test: Omnibox / 検索ホームのinputからsuggestion、選択、Navigation、History / Bookmark更新、Tab切替、cancelまでをfake clock / loader / providerで通す
- UI Test: keyboard、mouse、IME composition、focus、popup、検索ホーム・shortcut編集・背景変更・Home action、find bar、Search panel、narrow viewportをheadless Gio eventで検証する
- Visual Regression: Omnibox候補、source icon、selection、find highlight、zero match、Search panel、provider setting、検索ホームの背景・shortcut grid・focusをdesktop / narrowで固定する
- Differential Test: URL / IDNA / percent-encodeとUnicode normalizationを標準実装および固定Browser referenceと比較する
- Failure Test: stale response、timeout、oversize、malformed JSON / OpenSearch、profile破損、atomic write失敗、DOM mutation、Tab closeを決定的に再現する
- Privacy Test: opt-in前、URL / credential、command、localhost入力がremote endpointへ送られず、log / diagnosticへqueryを複製しないことを検証する

## 15. Search Showcase

networkへ依存しないSearch Showcaseを追加し、次のuser flowを一画面から再現できるようにする。

1. URL、英語query、日本語query、emoji、曖昧なhost、壊れたURLをOmniboxへ入力する
2. Tab、History、Bookmark、fake remote providerの候補とrankingを確認する
3. keyboard、mouse、IMEで候補を選び、current / new / background Tabへ開く
4. 長いLatin / CJK本文をページ内検索し、match移動、highlight、nested scroll、DOM mutationを確認する
5. provider追加、keyword切替、remote suggestion opt-in / off、timeout、oversize responseを確認する
6. History / Bookmark削除とindex再構築後に候補が残らないことを確認する
7. 初期Tab・新規Tab・Home actionから検索ホームを開き、中央検索欄とOmniboxで同じ候補・検索先・open dispositionになることを確認する
8. shortcutの追加・編集・削除・並び順と背景変更、設定復元・破損・上限超過、ホームからのNavigation後に候補が残らないことを確認する

Showcaseのfake providerは固定clockとchecked-in responseを使い、実検索provider、利用者の履歴、外部networkへ接続しない。

## 16. 実装フェーズ

### Phase 1 — Smart Omnibox

入力state、URL / query / command分類、submit disposition、popupのkeyboard / mouse interactionを実装する。

### Phase 2 — Search Provider and Suggestion Pipeline

provider model、安全なtemplate展開、local / remote suggestion、generation / cancel、deduplication、ranking、privacy設定を実装する。

### Phase 3 — Search Data and Local Index

Browsing History、Bookmark、atomic persistence、bounded local index、削除と再構築を実装する。

### Phase 4 — Find in Page

Unicode match、range、highlight、scroll、DOM / layout更新、Tabごとのfind stateを実装する。

### Phase 5 — Cross-Surface Search UI

Tabs / History / Bookmark Search panelとprovider settingを実装し、検索surface共通のresponsive UI、IME、accessibilityを整える。

### Phase 6 — Search Home and New Tab

共通の検索pipelineを使う中央検索欄、内部ホームviewとHome action、固定shortcut、同梱背景preset、設定保存と復旧、TabごとのLifecycleを実装する。Omnibox・provider・local data・Search panelの既存実装へ接続し、desktop / narrowの操作とvisual evidenceを固定する。

### Phase 7 — Quality and Release

Showcase、visual evidence、privacy / failure / performance gate、文書、package、全CIを完成する。

## 17. v0.21.0 非対象

- AI回答、要約、semantic embedding、vector search、画像・音声検索
- 広告、sponsored suggestion、検索query telemetry、個人profileに基づくranking
- private browsing mode、複数profile、account同期、他deviceのTab / History / Bookmark同期
- Bookmark folder / tag / import / export、Reading List、Tab group、閉じたTabの全文検索
- Page本文の全文index、offline Web index、crawler、検索結果Pageの独自rendering
- Browser password、form autofill、credit card、credential候補との統合
- arbitrary scriptを使うprovider、HTTP remote provider、POST検索template、認証必須provider
- Shadow DOM、generated content、canvas、image OCR、PDFを対象とするページ内検索
- 正規表現、fuzzy edit distance、stemming、形態素解析、言語別tokenizer
- 外部背景URL、画像アップロード、背景動画、自動shortcut生成、Google account連携、Doodle、feed / widget
- Chromium、Firefox、Safariとのsuggestion rankingおよびpixel完全一致
