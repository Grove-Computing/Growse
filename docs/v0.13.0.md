# Growse v0.13.0 スコープ定義書

## 1. 文書概要

本書は、Growse v0.13.0で実装するGo / JavaScriptデュアルRuntime、タブ単位の実行エンジン選択、JavaScript向けGrowse Web API、および診断Showcaseの範囲、完了条件、対象外を定義する。

v0.13.0は、v0.12.0までの複数Tab、WebGo Runtime、DOM / Style / Layout / Event、Fetch、Scheduler、Navigation、Storage、Page lifecycle、およびDevToolsが完成していることを前提とする。

既存ブラウザエンジン、WebView、Node.js互換環境、WASM、および任意Originのscript自動実行は使用しない。

---

## 2. リリーステーマ

> **GoとJavaScriptをタブ単位で選び、同じGrowse Web PlatformとDevTools上で比較・移行・実行できるデュアルRuntimeブラウザへ。**

利用者は既存WebGoアプリを維持したまま、同じPageに用意したGo版またはJavaScript版の処理を明示的に選択できる。両エンジンはGrowse固有のDOM、Network、Storage、Scheduler、Navigation、DevToolsへ接続し、エンジン切り替えによる状態漏洩を起こさない。

---

## 3. 準拠基準

- Go Runtimeは既存のYaegiとGrowse WebGo APIを維持する
- JavaScript言語処理はgojaが実装するECMAScript 5.1以上の対応範囲を基準とする
- JavaScript host APIは、WHATWG DOM、Console、HTML Timers、Fetch、History、Web Storageのうち本書で明示する操作と状態遷移を参考にする
- Scriptのtype判定はHTMLのMIME type規則を参考にし、Growseが明示したGo / JavaScript typeだけを受理する

ECMAScript、DOM、Fetch、HTML、Web IDL、および既存ブラウザ互換性全体への適合は宣言せず、本書で明示した対応範囲に限定する。

---

## 4. 目標

1. 各TabがGoまたはJavaScriptの実行エンジンを明示的に選択し、切り替えを完全なPage reloadとして適用できる
2. JavaScriptからConsole、DOM mutation、Event、Timer、Fetch、Storage、Navigationを既存Growse基盤上で利用できる
3. Go / JavaScriptのPage lifecycle、Origin policy、安全上限、DevTools観測を同じ規則で検証できる
4. 既存WebGoアプリ、Go API、複数Tab、履歴、描画、およびv0.12.0 DevToolsを回帰させない

---

## 5. 言語非依存Runtimeとエンジン選択

### 5.1 Runtimeモデル

Runtime共通層へ`go`と`javascript`を表す安定したEngine識別子を追加する。ScriptはEngine、Source URL、Source、inline属性を保持し、Browserは選択中Engineに属するScriptだけを文書順に取得してRuntimeへ渡す。

既存の`text/go`はGo Scriptとして維持する。JavaScriptはtype省略、空type、`text/javascript`、`application/javascript`を対象とする。`module`、import map、TypeScript、JSX、および未知のtypeは実行しない。

Goを既定Engineとする。既存のRuntime factory注入APIと`text/go`ページは呼び出し側の変更なしに動作する。

### 5.2 Tab単位の選択

Browser chromeへ現在Engineを示す`Go` / `JS`切り替えControlを追加する。選択状態はTabが所有し、新規TabはGoを選択する。別Tab、履歴entry、Local Storage、HTTP CacheへEngine選択を伝播しない。

Engine変更は現在URLの完全reloadとして扱う。変更前Runtimeをcancelして`Stop`し、Event listener、Timer、Animation Frame、Fetch callback、Storage listener、およびRuntime objectを解放した後、新しいEngineでDocumentを再取得する。reloadに失敗した場合も選択Engineを表示し、旧Runtimeを再利用しない。

同一Engineの再選択はno-opとし、same-document Navigation、戻る、進むではEngineを変更しない。通常reloadと強制reloadは選択中Engineを維持する。

### 5.3 Script取得とOrigin

自動実行は既存どおり`localhost`、`127.0.0.1`、`::1`のHTTP(S) Pageだけに限定する。外部ScriptはDocumentとsame-originであり、最終redirect URLもsame-originかつ信頼済みでなければ実行しない。

選択されていないEngineの外部Scriptは取得しない。Script load、parse、compile、runtime errorにはEngineを付与し、対象TabのConsoleだけへ記録する。

### 5.4 安全上限

- Scriptは1件2 MiB、選択Engineあたり64件、Page合計8 MiBを上限とする
- Engine切り替え中は古いNavigation completionとRuntime callbackを新しいPageへcommitしない
- Runtime instance、値、Event callbackをTab間またはEngine間で共有しない
- JavaScript RuntimeはOS、filesystem、process、Go reflection、およびNode.js APIを公開しない
- Runtimeは信頼できないコードを安全に実行するProcess Sandboxではないことを明示する

## 6. JavaScript Core、Console、DOM、Event

### 6.1 JavaScript Runtime

Pageごとに独立したgoja Runtimeと直列callback queueを生成する。inline / external Scriptを文書順に評価し、top-level完了後にBrowser Eventを受け付ける。JavaScriptの例外、syntax error、host API errorはGrowse processを終了させず、対象PageのRuntime errorまたはConsole recordに変換する。

Page cancelまたはEngine切り替え時は実行をinterruptできるものとし、終了後にJavaScript callbackを配送しない。goja Runtimeへ同時に複数goroutineから入らず、script、Event、Timer、Fetch completion、Storage eventを同じPage queue上で直列化する。

### 6.2 Console

`console.log`、`console.info`、`console.warn`、`console.error`を提供する。複数引数を空白で連結し、文字列、number、boolean、null、undefined、およびobjectを循環で停止する安全な表現へ変換する。DevToolsにはEngine=`javascript`とlevelを付け、既存の1件4 KiB・Page 1,000件上限を適用する。

### 6.3 DOM

`document.getElementById`、`document.querySelector`、`document.createElement`を提供する。Elementは少なくとも`textContent`、`value`、`getAttribute`、`setAttribute`、`appendChild`、`remove`、`classList.add`、`classList.remove`を提供し、既存WebGo DOM APIと同じNodeID・mutation・style再計算経路を使用する。

内部Node pointerをJavaScriptへ公開せず、異なるDocumentのElement追加、切断済みElement操作、無効なtag / attribute / selectorを安全に拒否する。

### 6.4 Event

Elementへ`addEventListener`を提供し、`click`、`input`、`change`、`submit`、`reset`、`focus`、`blur`、`mouseenter`、`mouseleave`を扱う。Eventは`type`、`target`、`value`、`clientX`、`clientY`、`preventDefault`を提供する。

listenerはPageあたり10,000件を上限とし、同じfunction・type・Elementの重複登録を増加として扱わない。Event callbackの例外はConsoleへ記録し、Browser default actionと他Tabを停止させない。Page終了時にすべてのlistenerを解放する。

## 7. JavaScript Scheduler、Fetch、Storage、Navigation

### 7.1 Scheduler

`setTimeout`、`setInterval`、`clearTimeout`、`clearInterval`、`requestAnimationFrame`、`cancelAnimationFrame`を提供し、既存Page Schedulerへ接続する。Timer ID、登録順、nesting、hidden Tab clamp、1 turn callback budget、Animation Frame timestamp、およびPage終了時cancelはWebGoと同じ規則を使用する。

文字列形式のTimer callbackは受理せず、functionだけを登録できる。callback引数は登録時に保持し、別Runtimeへ移動しない。

### 7.2 Fetch

`fetch(input, init)`をPromiseとして提供する。v0.13.0ではstring URL、method、Headers相当object、text body、credentials、AbortSignal、timeoutを対象とする。Responseは`status`、`statusText`、`url`、`redirected`、`ok`、read-only headers、および一度だけ消費できる`text()` / `json()` Promiseを提供する。

既存のSame-Origin Policy、CORS、Cookie、forbidden Header、Request 1 MiB、Response 4 MiB、Header 100件 / 64 KiB、redirect 10回、Page / Session同時実行上限を再利用する。Network completionとPromise reactionはPage queueへ戻し、終了済みPageではsettleしない。

### 7.3 Storage

`localStorage`と`sessionStorage`へ`getItem`、`setItem`、`removeItem`、`clear`、`key`、`length`を提供する。値はstringとして既存Origin別Areaへ保存し、quota、永続化、Tab別Session Storage、transaction rollbackをWebGoと共有する。

別Tabのsame-origin Local Storage変更は`storage`Eventとして配送する。更新元Tab、cross-origin Tab、終了済みPageへ配送しない。

### 7.4 LocationとHistory

read-onlyの`location.href`、`origin`、`protocol`、`host`、`hostname`、`port`、`pathname`、`search`、`hash`と、`location.assign`を提供する。`history.back`、`forward`、`go`、`pushState`、`replaceState`、`length`、`state`を既存Navigation / Historyへ接続する。

History stateはJSONへ変換可能な値だけを受理し、1件64 KiB・Session 4 MiB上限、same-origin URL、credential拒否を適用する。`popstate`と`hashchange`はPage queueで配送する。

## 8. DevToolsとエンジン観測

ConsoleのRuntime / script recordへEngineを表示し、Page概要で選択中Engineと起動状態を確認できるようにする。Network panelのScript requestはGo / JavaScriptを区別するが、Request / Response body、Header、Cookie、Authorizationを保持しない。

Inspectorは両Engineが変更した同じDOM、Computed Style、Layout boundsを表示する。DevToolsからGo / JavaScript codeを評価するREPLは提供しない。

---

## 9. テスト方針

- Unit Test: Engine/type判定、factory選択、goja lifecycle、Console変換、DOM wrapper、Event、Timer、Fetch Promise、Storage、History、安全上限を決定的に検証する
- Integration Test: 同じPageのGo / JavaScriptを切り替え、旧Runtime停止、DOM更新、Event、Fetch、Storage、Navigation、DevTools record、Tab分離を検証する
- Visual Regression: Browser chromeのEngine selectorとGo / JS両モードのDevTools状態をgoldenで固定する
- Conformance Test: 対応するECMAScript / DOM / HTML / Fetch / Storage / Historyの最小fixtureを、非対応範囲を明記して比較する
- Security Test: untrusted / cross-origin Script、redirect、終了後callback、無制限listener、文字列Timer、credential露出、OS API非公開を検証する

---

## 10. Showcase

`examples/dual-runtime`へ、同じCounter / Todo操作をGoとJavaScriptの両方で実装したlocalhost fixtureを追加する。利用者はTabのEngine selectorを切り替え、reload後も同じHTML / CSS上でDOM Event、Timer、Fetch、Storage、Navigationが動作することを確認できる。

ShowcaseはEngine名を画面とConsoleへ表示し、成功Fetch、失敗Fetch、Timer、Local Storage、History、Runtime errorをDevToolsで比較できるようにする。外部Internet、外部API、時刻依存データは使用しない。

## 12. v0.13.0 非対象

- V8、SpiderMonkey、JavaScriptCore、QuickJS、WebView、Chromium、Node.js、npm module resolution
- ECMAScript modules、dynamic import、import map、TypeScript、JSX、WebAssembly、Service Worker、Web Worker
- `eval`や`Function`のGrowse host API拡張、DevTools REPL、Source debugger、breakpoint、heap profiler
- Window / iframe / opener、Shadow DOM、MutationObserver、custom elements、Canvas、WebSocket、WebRTC
- 任意の公開Internet OriginでのGo / JavaScript自動実行、Process Sandbox、Site Isolation、完全なCPU / memory sandbox
- GoとJavaScriptの同時実行、Runtime object・function・listenerのEngine間共有、ソースコードの自動変換
- 既存Webサイト、npm package、Web Platform Test全体との互換性宣言

## 14. Growse v0.13.0の定義

Growse v0.13.0とは、

> **Goを既定Engineとして既存WebGo互換性を保ちながら、Tab単位でJavaScriptへ切り替え、同じGrowse DOM、Event、Scheduler、Fetch、Storage、Navigation、DevTools基盤上でPage lifecycleとOrigin境界を維持して実行できるデュアルRuntime Release。**

を満たすReleaseである。
