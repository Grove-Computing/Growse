# Growse v0.18.0 スコープ定義書

## 1. 文書概要

本書は、Growse v0.18.0で実装する **Browser-grade Resource Loading and Interaction** の範囲、完了条件、対象外を定義する。v0.17.0までに導入したJavaScript Engine、framework fixture、非同期画像処理、resource cacheを前提に、画像、stylesheet、font、classic / module script、iframeを読み込む間もTab操作、入力、表示更新を継続でき、取得したresourceを実際に描画・操作できるBrowserへ近づける。

v0.18.0はChromiumやFirefoxの埋め込みを行わない。Growse自身のresource loader、DOM、JavaScript runtime、layout / paintを維持し、標準的なHTML pageでのresource lifecycleを観測可能かつ有限にするReleaseである。

---

## 2. リリーステーマ

> **画像、stylesheet、font、scriptを優先度・並列性・キャンセル・段階的commit・描画・入力まで一貫して扱い、読み込み中も操作を止めないBrowser-grade Resource Loading and Interactionへ。**

利用者はJavaScript Engineを選択したTabで、画像の多いPageや複数scriptを持つPageを開いても最初のPage表示を待たされず、viewport内の重要resourceが先に現れ、NavigationやTab close後の古いresourceが新しいPageへ影響しないことを期待できる。

---

## 3. 準拠基準

- HTML Living Standardの`img`、`picture`、`script`、`link`、`iframe`の本書で列挙するfetch、load、error、lazy loading lifecycle
- Fetch StandardとHTMLのCORS、redirect、MIME、resource cancellationの既存clientが扱う範囲
- `fetchpriority`、`loading=lazy`、`async`、`defer`、module scriptの優先順位と実行順序
- v0.17.0の固定Next.js / SvelteKit / Tailwind fixtureと、local multi-origin serverによる再現可能な統合Test

完全なnetwork stack、HTTP/2 / HTTP/3 priority、Service Worker cache、audio / video再生、全画像codec、任意公開siteとの完全互換は宣言しない。

---

## 4. 目標

1. Pageの初期commitを画像decodeやviewport外resourceの完了から分離し、画像は小さい後続commitで反映する
2. 同じPage内の重複image / background requestをcoalesceし、bounded worker queueとbyte / entry上限の内側で並列に処理する
3. parser-inserted classic / defer / async / module scriptを、fetch並列性とHTMLの実行順序を両立して扱う
4. `loading=lazy`、`fetchpriority`、viewport proximity、CSS backgroundを同一の優先度規則で扱い、優先度の観測をTestで固定する
5. Navigation、viewport変更、Page close、Engine切替でresource queue、in-flight fetch、staged completionをcancelし、古いgenerationを配送しない
6. framework fixtureとsmoke testで、画像・scriptが遅い場合にも初期表示と操作が継続することを検証する
7. 取得成功した画像・stylesheet・fontの結果をlayout / paintへ確実に反映し、主要なform controlとlinkをpointer / keyboardで操作できるようにする
8. `go run ./cmd/growse`で起動したdesktop appをcomputer useで操作し、local fixtureと代表的な公開siteをReleaseの最終品質gateとして検証する

---

## 5. 大項目別の仕様と安全上限

### 5.1 非同期画像とincremental commit

初期Navigationとviewport更新は画像fetch / decodeの完了を待たずにPageをcommitする。画像結果はgeneration確認後にstageし、読み出し時または次の更新でまとめてcommitする。同一URLはPage generation内で1回だけfetchし、background imageも同じcacheを通す。

- worker数、queue長、decoded byte、surface byte、cache entry数は既存の有限上限を越えない
- 破損画像、decode bomb、queue飽和、cancelはresource単位の有限diagnosticとplaceholderへ変換する
- Page closeまたはNavigationでcacheとfetch contextをcancelし、stale image eventを送らない

### 5.2 Script fetchと実行lifecycle

external classic、`defer`、`async`、module scriptのfetchをbounded queueで並列化する。document orderが必要なscriptはfetch完了順で実行せず、HTMLの定める実行順を保つ。失敗・cancel・MIME拒否は後続の独立scriptを停止させず、runtime diagnosticsへresource単位で記録する。

- script source、module graph、response body、queue、diagnosticは既存Page上限に従う
- `async` scriptの順序は保証せず、`defer`とparser-inserted classic scriptの順序を壊さない
- EngineがGoの場合はJavaScript scriptをfetch・実行しない

### 5.3 Resource priorityとlazy loading

`fetchpriority=high|low|auto`、`loading=lazy`、viewport内外、background image、script種別を共通priorityへ写像する。高優先度のvisible resourceは低優先度のlazy resourceに不当に待たされず、queue飽和時の却下は診断できる。

- attribute値はASCII case-insensitiveに正規化し、不正値は`auto`として扱う
- priorityはfetch順序を制御するが、scriptの実行順序やresourceの安全上限を緩和しない

### 5.4 Lifecycle、cache、診断

resource requestはPage generationに所有させ、Navigation、close、Engine切替、viewport更新の競合で新しいPageへ漏らさない。cache hit / miss / coalesced request / cancellation / queue rejectionを、秘匿URLやresponse bodyを含めずに検査可能にする。

- cancellation待ちでUI lockを保持しない
- background workerはPage終了後に残らず、結果を古いDOM nodeへ適用しない
- diagnosticsは上限付きで、credential、query、body、decoded pixelを出力しない

### 5.5 実fixture、回帰、Release品質

Next.js / SvelteKit fixture、画像を遅延させるsmoke page、multi-origin loaderを使い、cold / warm load、viewport変更、Navigation、cancel、cache reuse、script順序を検証する。Go Engineの既存表示はJavaScript resource lifecycleを開始しないことを回帰Testで固定する。

### 5.6 描画commitとpage interaction

resource fetchの成功だけを完了とせず、decode済み画像、CSS background、stylesheet、fontが現在generationのlayout / paintへ反映されたことまで検証する。`button`、`a`、text inputなどの主要なinteractive elementは、scroll後を含めてpaint結果とhit-test領域が一致し、pointerとkeyboardの双方から操作できるようにする。

- image completionは再layout / repaintを要求し、`picture`のfallback sourceを含む取得済み画像をplaceholderのまま残さない
- native form control相当の既定styleが欠けても、文字、背景、境界、focus状態を識別可能にする
- Tab作成、Tab切替、Navigation後もaddress barとpage inputのfocus所有者を一意にし、入力を破棄しない
- click、Enter、Back、Reloadの操作は同じNavigation lifecycleとgeneration規則を通す

### 5.7 Desktop実機Release gate

最終PRの必須CIが成功しmerge可能になったheadで、`go run ./cmd/growse`によりdesktop appを起動し、computer useで実際のwindowを操作する。固定local fixtureに加え、代表的な公開siteを開き、resourceの可視化と基本操作を目視確認する。自動Testの成功だけではこのgateを代替しない。

- local modern-web fixtureでstylesheet、font、module graph、PNG / SVG、hydration、button、link、Navigationを確認する
- 代表的な公開siteで画像、本文layout、scroll、link、入力、Back / Reload、Tab操作を確認する
- tabをerrorへ遷移させる未処理Runtime error、process panic、操作不能なfocus / hit-testずれを残さない
- 検証日時、対象head、操作結果、必要なcaptureをRelease PRへ記録する

## 6. テスト方針とShowcase

- Unit Test: priority mapping、queueの安定順序、cache coalescing、decode / fetch cancellation、script scheduleとfailure isolation
- Integration Test: 遅い画像とscriptを持つlocal pageで初期Page commit、後続image commit、Navigation / close時のstale result抑止を確認する
- Showcase / smoke: `cmd/growse-smoke` とmodern-web-compat fixtureでviewport内画像の段階表示、script hydration、background imageを確認する
- Desktop E2E: `go run ./cmd/growse`で起動した実windowをcomputer useで操作し、描画、scroll、link、button、入力、Back / Reload、Tabを確認する
- Quality Gate: 対象package Test、`go test ./...`、`make ci`、GitHub Actionsを各大項目PRで実行する

## 7. 実装フェーズ

1. 非同期画像とincremental commitの安定化
2. Script fetch / execution lifecycleのbrowser互換化
3. Resource priorityとlazy loadingの導入
4. Navigation / cache / diagnostics lifecycleの強化
5. 実fixture・品質・Release検証
6. 描画commit、hit-test、focus、既定control styleの実用化
7. desktop実機Release gateと公開site回帰の修正

---

## 8. v0.18.0 非対象

- Chromium、Firefox、WebKit、WebViewの埋め込みまたは描画委譲
- HTTP/2 / HTTP/3のwire-level priority、DNS prefetch、speculation rules、Service Worker cacheの完全実装
- video / audio playback、Media Source、DRM、WebRTC、WebGL、WebGPU
- AVIFを含む全画像codecの無条件対応、任意公開siteとの完全なresource互換
- Go EngineでのJavaScript script、module、hydration、JavaScript専用cacheの実行
- tag pushまたはGitHub Release公開

- [x] 同一画像URLとCSS backgroundをPage内cacheでcoalesceし、bounded worker queueで並列に処理する

- [x] cancelされたdefer / module script fetchがscriptを返さず、Navigation / Page closeのcontextへ古い結果を渡さない
