# Growse v0.16.0 スコープ定義書

## 1. 文書概要

本書は、Growse v0.16.0で実装するReal-site Rendering & Performance、すなわちTailwind CSS v4で生成された実用的なstylesheet、日本語を含むsystem font fallback、画像を含むPage、CSS / JavaScript animationを、利用者がJavaScript Engineを明示選択したTabで正しく軽快に表示するための範囲、完了条件、対象外を定義する。

v0.16.0は、v0.15.0までのModern Web Compatibility、Go / JavaScript Dual Runtime、Growse独自DOM / CSS / Layout / Paint、およびNext.js / SvelteKit / Tailwind fixtureが完成していることを前提とする。

本Releaseは[Issue #96](https://github.com/Grove-Computing/Growse/issues/96)の再現条件をRelease判定へ固定する。Chromium、WebKit、Gecko、WebViewを埋め込まず、Growseが所有するparser、style、font、image、layout、paint、animation lifecycleを改善する。

---

## 2. リリーステーマ

> **Tailwind CSS v4の実サイトを、日本語、画像、animationを含めて正しく軽快に表示できるReal-site Rendering & Performance Releaseへ。**

利用者はJavaScript Engineを明示選択したTabで、Next.jsまたはSvelteKitがSSRしたHTMLとframework CSSを本来のlayout、spacing、color、typographyに近い形で確認し、hydration後の操作とanimationを継続できる。画像やanimationが存在しても、同じimageのdecode / resize / rasterizeと静的display list構築をframeごとに繰り返さない。

新規Tabの既定はGo Engineのままとする。JavaScript Engine用のcompatibility profile、system font選択、hydration、animation schedulerはGo Runtimeのobject、callback、task queueと共有しない。

---

## 3. 準拠基準

- CSS Syntax Level 3のescape、identifier、invalid selector list recoveryの該当範囲
- Selectors Level 4の`:root`、`:host`、`:open`、forgiving selector list、およびunsupported selectorを含むlistの回復規則
- CSS Custom Properties、Values and Units、Media QueriesのTailwind CSS v4生成物が使用する範囲
- CSS FontsとGio text shapingのsystem family、fallback、script coverageの該当範囲
- HTML Living Standardのimage request、decode、intrinsic size、lazy loading、animation frame lifecycleの該当範囲
- CSS Transforms、Opacity、Animations、および`requestAnimationFrame()`の本書で列挙する範囲

Tailwind CSS、Next.js、SvelteKit、公開Webサイト、CSS全体、すべてのsystem font、すべての画像形式、およびpixel parityへの完全適合は宣言せず、本書のfixture、visual regression、benchmark、選定testで観測できる範囲に限定する。

---

## 4. 目標

1. Tailwind CSS v4のtheme custom propertyとescaped utility classを失わず、主要なspacing、grid、color、radius、max-widthをcomputed styleへ反映する
2. 日本語を含むPage textをtofuへせず、Page用font fallbackをBrowser chromeから分離して安定したlayoutとpaintを行う
3. imageのfetch、decode、resize、rasterize結果をPage generationと表示条件に応じて再利用し、不要な全image再走査を除去する
4. transform / opacity中心のanimation frameで静的layout treeとdisplay listを再構築せず、停止・非表示・reduced motion時の無駄なframeを抑止する
5. 実際のTailwind CSS v4 build artifactをoffline fixtureへ固定し、正しさと性能をCIで再現可能にする
6. Go EngineのJavaScript非実行、runtime分離、既存Showcase、Navigation、複数Tabを回帰させない

---

## 5. Tailwind CSS v4 grammarとcomputed style

### 5.1 Selector list回復

Tailwind CSS v4が生成する`:root,:host`をparseし、Document treeでは`:root`をmatchingさせる。Shadow DOMを実装しない範囲では`:host`を構文として受理して非matchingとし、unsupported selectorが含まれることだけを理由に有効なselectorまで破棄しない。

通常selector listと`:is()` / `:where()`のforgiving selector listを区別する。未知pseudo-classは誤matchingさせず、影響するselectorだけを局所的に無効化し、Stylesheet全体や同一ruleの有効selectorを失わない。

### 5.2 Escaped utility class

CSS identifier escapeをtokenize / decodeし、`.sm\\:grid-cols-2`、`.hover\\:bg-*`、arbitrary valueで使用されるescaped punctuationをDOMの実class値と照合する。escape後のidentifierをselector specificityとdiagnosticで一貫して扱う。

responsive utilityは既存media query評価へ接続し、viewport変更後に正しいrule setを再評価する。未知variantは誤適用せず、対応selectorだけを無効化する。

### 5.3 Theme custom propertyとvalue

Tailwind CSS v4のtheme blockから`--spacing`、`--color-*`、`--radius-*`、`--container-*`をCascadeへ保持し、`calc()`、`var()`、color、radius、max-widthをcomputed style、layout、paintへ接続する。

Custom Propertyの循環、未定義fallback、無効な型、深さ・size上限は影響するdeclarationへ局所化する。JavaScript Engineのcompatibility profileで実サイト向け診断を有効化し、Go RuntimeへJavaScript taskやhydration callbackを公開しない。

### 5.4 安全上限

- selector escapeは既存selector長、token数、nesting深さ上限へ従い、decode後のNULとinvalid code pointをreplacement characterとして扱う
- unknown pseudo-class、invalid escape、Custom Property循環でStylesheet全体を停止しない
- compatibility profileをPage generationへ固定し、Engine切り替え後のStyle resultを再利用しない

---

## 6. CJK font fallbackとshaper分離

JavaScript Pageのtext shaperはBrowser chromeのtheme shaperから分離する。Pageが`system-ui`、sans-serif、serif、monospaceを指定した場合は利用可能なsystem font collectionからglyph coverageを持つfamilyへfallbackし、日本語、Latin、記号を同一runまたは適切なrun分割で描画する。

system font discoveryに失敗した環境では同梱fallbackへ決定的に終端し、missing glyphをpanicや無限fallbackにしない。font family、weight、style、size、locale、textを含むbounded shaping cacheをPage generation内で再利用する。

Browser chrome、address bar、DevTools、別TabのthemeをPageのfont設定で書き換えない。Page close、Navigation、Engine切り替え後にPage shaperとcacheを解放し、stale font completionを新しいPageへ適用しない。

---

## 7. Image pipelineとresource cache

### 7.1 Decodeとresize cache

同一Page generationの同一image resourceは、fetch body、decoded source、orientation / intrinsic sizeを共有する。target pixel size、device scale、object-fit / object-position、source revisionをkeyとするbounded resize / paint cacheを設け、同一条件のframeでCatmullRom resizeやNRGBA allocationを繰り返さない。

late loadまたはDOM mutationでは影響するimageだけを更新し、Document内の全`img`を再走査・再decodeしない。src、srcset、sizes、viewport、device scaleが変化した場合だけcandidate選択と必要なcache entryを更新する。

### 7.2 Paint resource cache

background image、gradient、filter、maskなど静的visual resourceのrasterized resultをgeometry、style revision、device scaleにより再利用する。layout sizeまたはpaint-affecting styleが変わった場合は対象entryだけを破棄する。

### 7.3 Lifecycleと上限

- cacheはPage / Frame / generationを跨いでstale DOMやcredential付きresourceを参照しない
- decoded surface、resized surface、raster effectへ個数・byte上限とLRU evictionを設ける
- decode error、oversized image、allocation失敗はplaceholderへ局所化し、animation schedulerと別Tabを継続する
- animated GIF / WebPの全Frame再生は対象外とし、静止Frameのcache semanticsを保証する

---

## 8. Animationと差分描画

transform / opacityのみを変更するCSS animation、transition、`requestAnimationFrame()`について、基準layout treeと静的display listを保持し、frameごとにanimated propertyを合成してpaintする。layout-affecting propertyが変化した場合だけStyle / Layout / display listを再構築する。

image、background、gradient、filterの静的paint commandは前節のcacheを再利用する。animationが終了したPage、viewport外または非表示のTab、Page close後、Engine切り替え後はframe invalidationを停止する。`prefers-reduced-motion`では既存media queryとschedulerを整合させる。

frame budget、連続task、dirty node、animation数へ上限を設け、budget超過時はframeを間引いて入力、Navigation、別Tabを優先する。時刻を固定できるtest clockにより、animation sampling、終了、cancel、stale generationを決定的に検証する。

---

## 9. 実サイトfixtureと診断

RepositoryへTailwind CSS v4 CLIで生成したstylesheet artifactとSvelteKit SSR相当のHTMLを追加する。fixtureはversion、生成command、license、digestをmanifestへ固定し、CI時にnpm registry、CDN、公開DNS、時刻、system credentialを要求しない。

fixtureは`:root,:host` theme、escaped responsive class、grid、spacing、color、radius、max-width、日本語、複数image、background、transform / opacity animation、hydration後の操作を含む。公開サイト`https://saku0512.com`は手動比較に利用できるが、CIの合否条件にはしない。

DevToolsにはselector / declarationの局所的な無視理由、font fallback family、image cache hit / miss / eviction、frame中のlayout / display-list rebuild理由を件数上限付きで表示できるようにする。resource body、decoded pixel、credentialは診断へ複製しない。

---

## 10. テスト方針

- Unit Test: selector list recovery、CSS escape、pseudo-class matching、Custom Property cascade、font fallback、cache key / eviction、dirty classification、animation samplingを検証する
- Integration Test: local fixture serverでSSR HTML、Tailwind artifact、日本語、image mutation、Navigation、Engine切り替え、hydration、animation cancelを検証する
- Visual Regression: 固定viewport、scale、font fixture、clockでTailwind Pageの初期表示、responsive状態、hydration後、日本語、image load後、animation sampleを比較する
- Performance Test: warm image frameでdecode / resize / raster allocationが増えないこと、transform / opacity frameでlayout / display-list rebuildが増えないことをcounterとbenchmarkで検証する
- Regression Test: Go EngineでJavaScript request / hydration / animation taskが発生せず、Browser chromeのshaperと既存Go Showcaseの結果が変化しないことを検証する
- Security Test: malformed CSS escape、巨大image、cache churn、animation storm、stale generation、font discovery失敗を有限errorへ変換できることを検証する

## 11. Showcase

`examples/modern-web-compat`へreal-site rendering routeを追加する。利用者はJavaScript Engineを明示選択し、Tailwind CSS v4のcard / grid / tab / list、正しい日本語、複数画像、responsive layout、transform / opacity animation、hydration後のfilter操作を確認できる。

同じrouteをGo Engineで開いた場合はSSR HTMLとEngine非依存resourceだけを表示し、JavaScript hydration、`requestAnimationFrame()` callback、JavaScript animation stateを開始しない。diagnostic modeではcache counterとframe rebuild理由をDevToolsで確認できる。

### Phase 2 — CJK font fallbackとshaper分離

Page / chrome shaper分離、system font discovery、glyph fallback、shaping cache、lifecycleを実装する。

### Phase 3 — Image pipelineとresource cache

resource単位更新、decode共有、resize / paint cache、LRU、generation invalidation、計測counterを実装する。

### Phase 4 — Animationと差分描画

animated property分類、静的display list再利用、composite update、frame suppression、budget、test clockを実装する。

### Phase 5 — 実サイトfixtureと品質

Tailwind CSS v4 artifact、SvelteKit SSR相当fixture、visual / performance regression、DevTools診断、文書、全CIをv0.16.0へ同期する。

## 13. v0.16.0 非対象

- Go EngineからのJavaScript classic / Module / hydration / `requestAnimationFrame()`実行、URLやsiteによる自動Engine切り替え
- Go RuntimeとJavaScript Runtime間のobject、callback、task queue、animation state、font cacheの共有
- Shadow DOM、custom elements lifecycle、`:host-context()`、Web Components全体
- 任意versionのTailwind CSS、Next.js、SvelteKit、任意公開サイトとの完全互換またはpixel parity
- full Unicode shapingを同梱fontだけで保証すること、OSに存在しないscriptのglyph生成
- animated GIF / WebP / SVG animationの全Frame再生、video、Canvas、WebGL、WebGPU
- arbitrary filter graph、3D compositor、GPU renderer、subpixel exactness、browser engine同等のcompositing architecture
- 公開Webサイト、外部API、公開CDN、公開DNS、実credentialをRelease CIの合否条件にすること
