# Growse v0.12.0 スコープ定義書

## 1. 文書概要

本書は、Growse v0.12.0で実装するWebGo DevTools、すなわちConsole、DOM / Style / Layout Inspector、Network監視、診断Showcaseの範囲、完了条件、対象外を定義する。

v0.12.0は、v0.11.0までの複数Tab、WebGo Runtime、DOM / Style / Layout、Fetch、Cookie、CORS、HTTP Cache、およびPage lifecycleが完成していることを前提とする。

JavaScript、既存ブラウザエンジン、Chrome DevTools Protocol、およびWebGoコードの対話実行は使用しない。

---

## 2. リリーステーマ

> **WebGoアプリのConsole、DOM、Layout、Networkをブラウザ内で安全に観測し、問題を特定できる開発環境へ。**

利用者はF12または画面上のボタンでDevToolsを開き、active Tabに属するログ、Runtime error、DOM構造、Computed Style、Layout Box、HTTP処理を確認できる。表示情報はPageとTabのlifecycleに追従し、credential、password、Cookie、Authorization、URL userinfoを露出しない。

---

## 3. 準拠基準

- WHATWG Console Standardのlog levelとclearに関する限定的な観測モデル
- DOM StandardのDocument tree、node、attributeに関するread-only snapshot
- CSSOMのcomputed valueに相当するGrowse内部Computed Styleのread-only表示
- Fetch StandardとRFC 9110のrequest method、response status、redirect、およびtiming観測範囲
- OWASP Logging Cheat Sheetの機密情報除外原則

仕様全体やChrome / Firefox DevToolsとの互換性は宣言せず、本書で明示したread-onlyのGrowse DevToolsに限定する。

---

## 4. 目標

1. WebGo Console出力とRuntime / resource errorをactive Tab単位で時系列表示できる
2. DOM nodeを選択し、属性、Computed Style、Layout Boxをread-onlyで確認できる
3. Navigation、stylesheet、image、script、FetchのHTTP処理をcredentialを除去して観測できる
4. DevToolsの開閉、Tab切替、Navigation、Page closeで記録と選択状態を誤配送または漏洩しない
5. 記録件数、文字列長、Header数、Body非保持に安全上限を適用する

---

## 5. DevTools基盤とConsole

### 5.1 DevTools shell

Browser chromeへDevToolsボタンを追加し、F12で同じ開閉操作を行う。DevToolsはviewport下部に固定高さのread-only panelとして表示し、Console、Inspector、Networkのtabを切り替えられる。WebページのDOM、focus、scroll、Navigation Historyを開閉操作で変更しない。

DevTools stateはBrowserUIが所有し、active Tabごとに選択中panel、選択node、表示対象recordを分離する。Tab切替時は対象Tabのsnapshotへ切り替え、閉じたTabのstateは解放する。

### 5.2 Console record

`growse/console`のLog、Info、Warn、Errorをlevel、message、sequenceとともにPageへ記録する。外部script load error、compile / runtime errorもsource categoryを区別して記録する。Console panelはlevel filter、clear、最新recordへの追従を提供する。

messageは一件4 KiB、Pageあたり1,000件を上限とし、超過時は古いrecordから破棄する。recordは別Tabや次のPageへ継承せず、Page close後のcallbackによる追記を許可しない。

---

## 6. DOM / Style / Layout Inspector

DOM Inspectorはactive PageのDocumentをread-only treeとして表示し、element、text、document nodeを親子順に辿れる。node選択時はtag、公開可能なattribute、接続状態を表示する。password inputのvalue、event callback、Runtime object、Storage、Cookieは表示しない。

選択elementについて、Growseが保持するComputed Styleの主要値とLayout Treeのbox geometryを表示する。最低限display、position、color、background、width / height、margin、padding、border、opacity、transform、およびx / y / width / heightを確認できる。DOM mutation、style再計算、viewport変更後は次Frameでsnapshotを更新し、切断されたnode選択は解除する。

treeは最大2,000 node、深さ128、attributeはnodeあたり64件、表示文字列は一項目4 KiBを上限とする。上限到達時はPage動作を停止せずInspector表示だけをtruncatedとする。

---

## 7. Network監視とcredential redaction

Network panelはrequestごとにsequence、resource kind、method、credential除去済みURL、開始・終了時刻、duration、status、redirect、cache結果、response size、error categoryを表示する。Navigation、stylesheet、background image、external WebGo script、Form submission、WebGo Fetchを対象とする。

request / response Headerはallowlistした非機密fieldだけを表示し、Authorization、Proxy-Authorization、Cookie、Set-Cookie、WWW-Authenticate、Proxy-Authenticate、およびtoken / secret / keyを示すfieldを値ごと除外する。URL userinfoとfragmentを除去し、queryは既定でkeyだけを残してvalueを`[redacted]`へ置換する。request / response bodyは保持または表示しない。

Pageあたり500件、Session全体4,000件を上限とし、古いrecordから破棄する。redirect、cache hit、CORS rejection、abort、timeout、Page cancelを区別し、失敗したrequestが成功statusを持たないことを保証する。観測処理の失敗でnetwork request自体を失敗させない。

---

## 8. テスト方針

- Unit Test: bounded record store、sequence、filter、clear、DOM snapshot、style / layout projection、URL / Header redactionを検証する。
- Integration Test: local fixture serverとfake clockを使い、Navigation、Fetch、redirect、cache、CORS、abort、Tab切替、Page closeのrecord隔離を検証する。
- Visual Regression: DevToolsのConsole、Inspector、Network panelを固定Viewport、Font、Scaleで描画し、通常・空・error・truncated状態を検証する。
- Security Test: credential文字列を含むURL、Header、Cookie、password field、errorを入力し、UI snapshot、log、failure messageへ残らないことを検証する。

---

## 9. Showcase

`examples/devtools`を追加し、Console level、DOM mutation、Computed Style、Layout、成功Fetch、redirect、cache hit、HTTP error、timeoutをlocal fixtureだけで再現する。利用者はF12でDevToolsを開き、ConsoleからDOM、Inspectorから選択node、Networkから各requestの結果を確認できる。

Showcaseは外部Service、API key、Public Internet、実credential、実Profileを要求しない。

---

## 10. 実装フェーズ

### Phase 1 — DevTools基盤とConsole

- bounded record modelとPage / Tab lifecycleを実装する
- DevTools shell、F12、panel切替、Console filter / clearを実装する
- WebGo ConsoleとRuntime / resource errorをrecordへ接続する

### Phase 2 — DOM / Style / Layout Inspector

- bounded read-only DOM snapshotとnode選択を実装する
- Computed StyleとLayout Box projectionを実装する
- mutation、viewport、Tab lifecycleとの同期を検証する

### Phase 3 — Network監視

- request observerとresource kind、timing、cache、error recordを実装する
- URL / Header / errorのcredential redactionを実装する
- Navigation、resource、Fetch、Form、Tab / Page lifecycleを統合検証する

### Phase 4 — Showcaseと品質

- DevTools Showcase、README、設計文書、visual regressionを更新する
- Unit、integration、security、race、CI、成果物を検証する

---

## 11. v0.12.0 非対象

- ConsoleからのGo / JavaScript / shell code実行、REPL、Runtime object inspection
- DOM、attribute、CSS rule、Computed Style、Layout値のDevToolsからの編集
- Chrome DevTools Protocol、remote debugging、browser extension API
- request / response body、Cookie、Authorization、password、Storage値の表示またはexport
- waterfall chart、CPU / memory profiler、heap snapshot、coverage recorder
- Network requestの再送、編集、mock、throttling、HAR import / export
- DevTools windowの分離、dock位置変更、panel resize、custom theme

---
