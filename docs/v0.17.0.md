# Growse v0.17.0 スコープ定義書

## 1. 文書概要

本書は、Growse v0.17.0で実装するBrowser-grade Web Compatibility、すなわち実際のNext.js / SvelteKit / Tailwind CSS Pageを、利用者がJavaScript Engineを明示選択したTabで通常のdesktop browserに近いlayout、typography、visual、interaction、resource loading、animation性能で表示するための範囲、完了条件、対象外を定義する。

v0.17.0は、v0.16.0までのModern Web Compatibility、Real-site Rendering & Performance、Go / JavaScript Dual Runtime、およびGrowse独自DOM / CSS / Layout / Paintを前提とする。

v0.16.0は個別Featureと手製fixtureの期待値を満たしたが、実framework buildを参照browserと比較するRelease Gateを持たず、簡略化したUA style、未実装のformatting context / intrinsic sizing、frameworkが要求するWeb API、画像decodeとanimation paintの負荷が実Page全体では残った。v0.17.0はこの検証不足を解消し、見た目、操作、表示速度をPage単位で判定する。

---

## 2. リリーステーマ

> **実Next.js / SvelteKit / Tailwind CSS Pageを、参照browserとの差分とframe budgetで検証し、通常のbrowserらしく表示・操作できるBrowser-grade Web Compatibility Releaseへ。**

利用者はJavaScript Engineを明示選択したTabで、frameworkが生成したHTML、CSS、Module、画像、fontをそのまま読み込み、初期SSR表示からhydration、入力、Navigation、animationまで継続できる。画像の多いPageやanimation中もUI threadを長時間占有せず、入力、Scroll、Tab操作が応答し続ける。

新規Tabの既定はGo Engineのままとする。本ReleaseのUA compatibility profile、framework API、asynchronous image pipeline、compositor、browser-grade diagnosticsはJavaScript Engine専用とし、Go Runtimeのobject、callback、task queue、cache、animation stateと共有しない。

## 3. 準拠基準

- HTML Living StandardのUA rendering、replaced element、table、form control、image request、lazy loading、document lifecycleの本書で列挙する範囲
- CSS Display、Box Sizing、Positioned Layout、Tables、Flexbox、Grid、Text、Fonts、Backgrounds and Borders、Overflow、Transforms、Containmentの実fixtureが使用する範囲
- DOM、CSSOM View、UI Events、Encoding、Streams、Fetch、URL、History、Observer APIのframework runtimeが使用する範囲
- ECMAScript ModulesとNext.js / React、SvelteKit / Svelteの固定versionが生成するbrowser bundleの実行範囲
- Web Platform Testsの選定Testと、固定Chromium referenceから取得するgeometry / computed style / visual / interaction基準

仕様全体、全WPT、任意公開サイトとのpixel完全一致は宣言しない。一方で、本書で固定する実framework fixtureについては「未対応Featureだから比較対象外」とせず、参照browserとの差分をRelease failureとして扱う。

---

## 4. 目標

1. Browser相当のUA stylesheetと主要formatting contextを導入し、CSS未指定時を含むPage全体のlayoutとtypographyを参照browserへ近づける
2. 手製のframework風fixtureではなく、固定versionのNext.js / SvelteKit / Tailwind CSSが実際に生成した成果物をhydrateし、代表操作を完了できるようにする
3. image fetch、decode、resize、upload / raster、lazy loadを非同期かつ増分的に処理し、画像の多いPageでもBrowser UIと入力を停止させない
4. animationとScrollをdirty region / compositing layer単位で更新し、静的Page全体のStyle / Layout / Paintをframeごとに繰り返さない
5. Chromium referenceとのgeometry、computed style、visual、interaction、performance差分をlocalとCIで再現し、互換性退行をRelease Gateにする
6. Go EngineのJavaScript非実行と既存表示を維持し、JS Engine専用の互換処理がGo Runtimeへ流入しないことを証明する

## 5. Browser baselineとlayout互換

### 5.1 UA stylesheetとdefault rendering

JavaScript EngineのPageへversion管理されたUA stylesheetを適用し、`html`、`body`、heading、paragraph、list、table、link、image、form control、hidden elementなどのdefault display、margin、font、color、box sizing、focus outlineをbrowser相当へ揃える。UA ruleはAuthor ruleより低いoriginでCascadeし、利用者StyleやBrowser chromeのthemeへ漏らさない。

### 5.2 Formatting contextとintrinsic sizing

実fixtureが使用するtable formatting、`display: contents`、float / clear、replaced elementのintrinsic ratio、min-content / max-content / fit-content、automatic minimum size、percentage、absolute / fixed / sticky containing block、overflow / scroll extentをStyle、Layout、Paint、Hit Testで一貫させる。

Inline formattingは実font metrics、baseline、line box、whitespace、word breaking、ellipsis、inline replaced elementを同じshaping resultから構築する。日本語とLatinが混在するPageで行高、折返し、glyph fallbackの差が親要素へ累積しないようにする。

### 5.3 Visual property

実fixtureで使用されるpseudo-element content、attribute selector modifier、conic gradient、`data:` image、background origin / clip、outline、shadow、filter / backdrop、2D transform、stacking context、clip、opacityをcomputed styleからpaintへ接続する。未対応値はdeclaration単位に局所化し、兄弟ruleやPage全体を失わない。

### 5.4 安全上限

- UA stylesheetとAuthor stylesheetは既存のrule、selector、nesting、Custom Property上限へ従う
- table、float、intrinsic sizing、container queryの反復はPage単位の有限回数で収束させ、非収束時は診断付きの安定したfallbackへ終端する
- filter、blur、shadow、gradient、clipのsurface / kernel / layer allocationへpixel数とbyte上限を適用する
- compatibility profileはPage generationへ固定し、Engine切替、Navigation、別Tabへcomputed resultを再利用しない

---

## 6. 実framework hydrationとWeb API互換

### 6.1 固定framework build

固定versionのNext.js App Router、React、SvelteKit、Svelte、Tailwind CSSを実際のtoolchainでbuildし、prerendered HTML、framework CSS、Module chunk、font、image、manifestをlicense、生成command、lockfile、digest付きfixtureとして保存する。CIの実行時はnpm registry、CDN、公開DNSを必要としない。

### 6.2 DOM / CSSOM / browser global

framework起動時に使用されるNode / Element / Document / Window identity、namespace付きElement、template、Range相当の最小DOM操作、Event / Focus / Pointer、CSSStyleDeclaration、geometry、media query、Observer、URL、Encoding、Fetch body、ReadableStream相当のbounded consumer、performance clockを実Pageの要求から実装する。

不足APIを無条件の空stubで成功扱いにしない。対応APIはobservable semanticsをTestで固定し、非対応APIはfeature detectionが正しくfalseになり、framework errorをDevToolsへ原因付きで記録する。

### 6.3 Hydrationとclient Navigation

Next.jsとSvelteKitのSSR DOM identityを保持してhydrateし、button、form、dialog / menu相当のfocus操作、class / style mutation、async data更新、client-side route遷移、history traversalを実行する。hydration mismatch、Module評価失敗、未対応global、Event配送失敗をPage全体の無言停止にせず、該当resourceとcomponent境界へ局所化して診断する。

### 6.4 Runtime境界

- framework JavaScript、dynamic chunk、hydration、stream、observer、animation callbackは利用者がJS Engineを明示選択したTabだけで開始する
- Go Engineはframework JavaScriptをfetch / parse / evaluateせず、JS専用DOM wrapper、UA compatibility state、callback queueを生成しない
- Page close、Navigation、crash、timeout、Engine切替でworker、stream、observer、pending resource、callbackをcancelし、stale generationへ配送しない
- source、Module graph、DOM node、Event、stream buffer、task、diagnosticへ既存またはより厳しいPage単位上限を適用する

---

## 7. 非同期image / font / media pipeline

### 7.1 Resource scheduling

preload、`fetchpriority`、viewport proximity、`loading=lazy`、CSS background、font dependencyからresource priorityを決定する。fetch、decode、orientation、color conversion、resize / rasterをcancel可能なbounded worker queueへ分離し、UI threadではgeneration確認と小さいcommitだけを行う。

`picture` / `srcset` / `sizes` / DPRのcandidate選択、redirect、MIME sniffing、CORS、decode失敗をresource単位で扱う。PNG、JPEG、GIF、WebP、安全なSVGに加えて、platform decoderまたは純Go decoderで安全上限を適用できる場合はAVIFを扱う。

### 7.2 Incremental commitとcache

image completionは影響するreplaced elementまたはbackgroundだけをdirtyにし、intrinsic sizeが変わる場合だけ祖先Layoutを必要範囲で更新する。同一body、decoded source、scaled surface、paint commandをURL、validator、DPR、target、color / orientation、style revision付きで共有する。

animated GIF / WebPは表示中のcandidateだけをclockとframe disposal規則に従って進め、非表示、offscreen、reduced motion、Page closeでは停止する。Web Fontは必要glyph runだけを再shapeし、Page全体のtextとBrowser chromeを再構築しない。

### 7.3 Responsiveness budget

- resource queueはpriority別の同時実行数、decoded byte、surface byte、animated frame、Page合計memoryへ上限を持つ
- 1回のUI commitで処理するcompletion数とdirty node数を制限し、残りは次のtickへ公平に繰り越す
- decode bomb、巨大dimension、破損frame、cancel、allocation失敗をplaceholderとbounded diagnosticへ変換する
- cold / warm / scroll / mutation時のfetch、decode、resize、layout、paint回数と最大連続workをcounterで検証する

---

## 8. Incremental renderingとcompositor

### 8.1 Dirty propagationとdisplay list

DOM / Style mutationをstyle-only、layout subtree、paint-only、composite-onlyへ分類し、影響Nodeから必要なancestor / descendantへだけdirty stateを伝播する。Layout fragmentとDisplay Listを安定したNode / fragment identityで保持し、unrelated subtreeとviewport外contentを再構築しない。

### 8.2 Compositing layerとdamage region

transform、opacity、clip、scroll、fixed / sticky、filter、animationをbounded compositing layerへ昇格し、layer propertyとdamage regionだけをframeへ反映する。Scrollとtransform / opacity animationでは静的rasterを再利用し、viewport全体のclear、image resize、text shapingを繰り返さない。

### 8.3 Frame scheduling

vsync相当の単一frame schedulerへCSS Animation、Transition、`requestAnimationFrame()`、animated image、Scrollを統合し、同一tickのinvalidationをcoalesceする。入力とBrowser chromeをPage taskより優先し、長いtask、過剰animation、background Tabをbudget / throttle / cancel規則で制御する。

性能のRelease Gateはwork counterに加え、固定Linux runnerの代表fixtureでinput-to-next-frame、scroll frame、animation frame、image completion commitの分位値を記録する。環境差の大きい絶対時間だけで合否を決めず、v0.16.0 baselineからの退行率と再構築回数を併用する。

---

## 9. Browser differential conformanceと診断

### 9.1 Reference corpus

実Next.js、実SvelteKit、Tailwind typography / dashboard / article / form / image gallery / animation Pageをlocal multi-origin fixtureへ固定する。各Pageはdesktop / narrow viewport、DPR 1 / 2、初期SSR、font / image完了後、hydration後、操作後、scroll / animation sampleを持つ。

固定ChromiumでDOM landmark、computed style、bounding box、scroll extent、focus、network completion、screenshotを採取し、Growseの同一状態と比較する。text rasterやplatform font差はmask / semantic metricを併用するが、主要regionの消失、重なり、viewport逸脱、誤ったdisplay、操作不能を許容しない。

### 9.2 Release threshold

- 主要landmarkの位置とsizeは参照値との差を原則2 CSS px以内、または各軸1%以内に収める
- 検証対象のcomputed property、resource state、focus / Event、route、hydration markerは参照結果と一致させる
- screenshotは動的領域と許容font raster差をmaskしたperceptual diffをPageごとに2%以下とし、主要region単位の差分上限も持つ
- 画像galleryのwarm scrollとtransform / opacity animationでは、静的image decode / resize、全Document Layout、全Display List rebuildを0回にする
- 固定runnerでlong frame比率と入力待ち時間をv0.16.0 baselineから悪化させず、各fixtureに定めるbudgetを満たす

### 9.3 Diagnostics

DevToolsへunsupported CSS / Web API、hydration mismatch、long task、resource queue、decode / raster cache、dirty propagation、layer promotion、damage region、frame drop理由を件数上限付きで表示する。source body、credential、decoded pixel、framework stateを複製せず、Page / generation / node / resourceをredacted identifierで関連付ける。

## 10. テスト方針

- Unit Test: UA Cascade、table / float / intrinsic sizing、inline metrics、visual property、DOM / CSSOM / Event、resource priority、decode cancellation、dirty propagation、layer promotion、frame coalescingを検証する
- Integration Test: 実Next.js / SvelteKit buildをlocal serverから読み込み、SSR、Module graph、hydration、入力、async更新、client Navigation、image / font completion、Scroll、Engine切替を検証する
- Differential Test: 固定ChromiumとGrowseから同一scenarioのcomputed style、geometry、screenshot、focus、resource stateを採取し、許容差内で比較する
- Visual Regression: desktop / narrow、DPR 1 / 2、初期 / resource完了 / hydration / interaction / animation状態をregion別のsemantic snapshotとperceptual diffで比較する
- Performance Test: image gallery、animated hero、long listでcold / warm counter、allocation、dirty node、layer、damage、long frame、input latencyを記録する
- Regression Test: Go EngineがJavaScript resource、framework API、JS専用UA profile、image animation、compositor callbackを開始せず、v0.16.0のGo Showcaseが変化しないことを検証する
- Security Test: malformed CSS、decode bomb、animation storm、stream overflow、task starvation、stale generation、worker crashを有限errorと局所fallbackへ変換できることを検証する

## 11. Showcase

`examples/browser-grade-compat`へ、実Next.js App Routerと実SvelteKit static buildによる同内容のPageを追加する。Pageはheader / navigation、responsive grid、article typography、table、form、dialog相当interaction、CJK / Web Font、picture gallery、lazy image、animated image、sticky element、transform / opacity animation、client routeを含む。

利用者はJS Engineを明示選択し、初期SSR、resource完了、hydration、入力、Navigation、Scroll、animationを確認できる。DevToolsのCompatibility viewではChromium referenceとの差分、unsupported原因、resource queue、cache、dirty subtree、damage region、frame budgetを確認できる。

同じURLをGo Engineで開いた場合はSSR HTMLとEngine非依存resourceだけを表示し、framework JavaScript、hydration、animated image callback、JS専用compatibility profileを開始しない。

## 13. v0.17.0 非対象

- Go EngineからのJavaScript classic / Module / hydration / Observer / animation callback実行、URLやsiteによる自動Engine切替
- Go RuntimeとJavaScript Runtime間のobject、callback、task queue、UA compatibility state、resource cache、compositing layerの共有
- Chromium、WebKit、Gecko、WebViewの埋め込み、または既存browser engineへのrender委譲
- Node.js server runtime、npm package resolution、CommonJS、TypeScript / JSXの実行時変換
- WebGL、WebGPU、WebRTC、DRM、Media Source、full video / audio playback
- 任意公開サイト、全versionのNext.js / React / SvelteKit / Tailwind CSS、全WPT、全CSS仕様との完全互換
- platform固有font raster、subpixel antialiasing、GPU driver差を含む全pixelのbit一致
- Browser extension、password manager、autofill、accessibility tree全体、printing、PDF、vertical writing、fragmentationの完全実装
- 公開Webサイト、外部API、公開CDN、公開DNS、実credentialをRelease CIの必須条件にすること
