# Growse v0.2.0 スコープ定義書

## 1. 文書概要

### 1.1 対象バージョン

```text
Growse v0.2.0
```

### 1.2 本書の目的

本書は、Growse v0.2.0で実装する機能、完了条件、および対象外とする機能を定義する。

v0.2.0では、v0.1.0で成立した次の実行モデルを維持する。

```text
HTML = Structure
CSS  = Presentation
Go   = Behavior
```

JavaScriptエンジン、WebAssembly、WebView、および既存ブラウザエンジンは使用しない。

---

## 2. リリーステーマ

v0.2.0のテーマを以下とする。

> **WebGoで実用的なインタラクティブUIを構築できるようにする。**

v0.1.0では、既存要素の取得、テキスト変更、およびクリックイベントによってCounter Demoを実現した。

v0.2.0では、WebGoからDOM要素を動的に作成・追加・削除できるようにし、テキスト入力とフォームイベントを追加する。これにより、ページロード時に存在しなかったUIをGoコードから構築できることを証明する。

---

## 3. 目標

v0.2.0では、以下を達成する。

1. WebGoからCSSセレクターで要素を取得できる
2. WebGoからDOM要素を作成・追加・削除できる
3. WebGoから属性とクラスを操作できる
4. `<input type="text">`へキーボード入力できる
5. WebGoからinputの値を取得・変更できる
6. click、input、change、submitイベントをGoへ配信できる
7. イベントに対象要素や入力値などの情報を含められる
8. 動的DOM変更後にStyle、Layout、Paintを再実行できる
9. WebGoだけでTodo Demoを実装できる
10. WebGoのエラーによってGrowseプロセス全体が終了しない

---

## 4. DOM API

### 4.1 QuerySelector

`growse/dom`へ、最初に一致する要素を取得するAPIを追加する。

```go
element := dom.QuerySelector("#todo-list")
```

v0.2.0で対応するセレクターは以下とする。

- タグ: `button`
- ID: `#submit`
- クラス: `.todo`
- タグとクラス: `li.todo`

複雑な結合子、属性セレクター、疑似クラス、および`QuerySelectorAll`は対象外とする。

無効なセレクター、または一致する要素が存在しない場合は`nil`を返し、Runtimeを停止させない。

### 4.2 CreateElement

WebGoから要素を作成できるようにする。

```go
item := dom.CreateElement("li")
```

作成直後の要素はDocumentへ接続されていない。`AppendChild`によってDocument内の要素へ追加された時点で、レイアウトおよび描画の対象となる。

テキストノード専用の公開APIはv0.2.0では追加せず、要素のテキストは`SetText`で設定する。

### 4.3 AppendChild

要素を別の要素の末尾へ追加できるようにする。

```go
list.AppendChild(item)
```

次の場合、操作は失敗し、DOMを変更しない。

- 親または子が`nil`
- 親がDocumentに存在しない
- 循環参照が発生する
- 異なるDocumentに属する要素を追加しようとした

### 4.4 Remove

要素自身を親要素から削除できるようにする。

```go
item.Remove()
```

削除済み要素に対する再度の`Remove`は安全に失敗し、panicを発生させない。

削除された要素と子孫へ登録されていたイベントリスナーは、以後呼び出されないものとする。

### 4.5 Attribute

属性の取得と変更を可能にする。

```go
value, ok := element.GetAttribute("data-id")
element.SetAttribute("data-id", "42")
```

少なくとも以下の属性を扱えること。

- `id`
- `class`
- `value`
- `type`
- `data-*`

`id`または`class`の変更後は、セレクターマッチングとComputed Styleを再計算する。

イベントハンドラー属性など、文字列をコードとして実行する属性は実装しない。

### 4.6 Class

クラス文字列を直接解析せずに操作できるAPIを提供する。

```go
element.AddClass("completed")
element.RemoveClass("completed")
```

同一クラスの重複追加は行わない。存在しないクラスの削除は安全に無視する。

### 4.7 DOM変更通知

以下の操作でDOMが実際に変更された場合、Mutation通知を1回発生させる。

- `SetText`
- `AppendChild`
- `Remove`
- `SetAttribute`
- `AddClass`
- `RemoveClass`
- `SetValue`

Mutation通知後、アクティブページに対して以下を順番に更新する。

```text
DOM
  -> Selector Matching
  -> Computed Style
  -> Layout Tree
  -> Display List
  -> Gio Renderer
```

値が変化しなかった操作では、不要な再描画を要求しない。

## 5. テキスト入力

### 5.1 対応要素

v0.2.0では次の要素を入力対象とする。

```html
<input type="text">
```

`type`が省略された`input`もテキスト入力として扱う。

checkbox、radio、password、file、date、number、textarea、およびselectは対象外とする。

### 5.2 描画

テキストinputは少なくとも以下を描画する。

- 入力領域の背景
- 枠線
- 現在の値
- フォーカス状態
- キャレット

長い入力値の横スクロール、文字選択、コピー、貼り付け、およびIMEの完全対応はv0.2.0の完了条件に含めない。

### 5.3 フォーカス

クリックしたinputへフォーカスを移動する。

アクティブページ内で同時にフォーカスを持てる要素は1つとする。ページ遷移、再読込、または要素削除時にはフォーカスを解除する。

Tabキーによるフォーカス移動は任意実装とし、完了条件には含めない。

### 5.4 Value API

inputの値を取得・変更できるようにする。

```go
value := input.Value()
input.SetValue("")
```

input以外の要素に対する`Value`は空文字列を返す。input以外の要素に対する`SetValue`はDOMを変更しない。

ユーザー入力と`SetValue`の双方で、DOMが保持する値と画面表示が一致すること。

## 6. Form

### 6.1 対応範囲

v0.2.0では、Todo Demoの入力確定に必要な最小限のformを実装する。

```html
<form id="todo-form">
    <input id="todo-input" type="text">
    <button type="submit">Add</button>
</form>
```

submitボタンのクリック、またはフォーカス中のテキストinputでEnterキーを押した場合、formへsubmitイベントを配信する。

HTTPリクエストによるフォーム送信、`action`、`method`、multipart/form-data、入力検証、およびブラウザ標準のページ遷移は実装しない。

## 7. Event API

### 7.1 イベント種類

v0.2.0では以下を扱う。

| イベント | 発生条件 |
| --- | --- |
| `click` | 対象要素がクリックされた |
| `input` | ユーザー操作でinputの値が変化した |
| `change` | inputの編集が確定した、またはフォーカスを失った |
| `submit` | formが送信操作を受けた |

### 7.2 Event

イベント情報をWebGoへ渡す型を追加する。

```go
type Event struct {
    Type     string
    TargetID string
    Value    string
    X        float32
    Y        float32
}
```

イベントに存在しない情報はゼロ値とする。

公開するEvent型はGrowse内部のNodeポインターを保持せず、WebGoから内部DOMを直接変更できない構造とする。

### 7.3 ハンドラー登録

既存の引数なし`OnClick`は互換性のため維持する。

```go
button.OnClick(func() {
    console.Log("clicked")
})
```

イベント情報が必要な場合は、次のAPIを提供する。

```go
button.OnClickEvent(func(event dom.Event) {})
input.OnInput(func(event dom.Event) {})
input.OnChange(func(event dom.Event) {})
form.OnSubmit(func(event dom.Event) {})
```

同じ要素へ複数のハンドラーを登録した場合は登録順に呼び出す。

### 7.4 エラー分離

イベントハンドラー内でpanicが発生しても、次を保証する。

- Growseプロセス全体を終了しない
- エラー内容とイベント種類をログへ記録する
- 他のページまたは次のユーザー操作を可能な限り継続する

### 7.5 非対象

以下はv0.2.0では実装しない。

- Event Bubbling
- Event Capture
- `preventDefault`
- `stopPropagation`
- キーボードイベントの汎用WebGo API
- マウス移動、ホバー、ドラッグイベント

## 8. Todo Demo

v0.2.0の統合デモとして、`examples/todo`を追加する。

Todo Demoは次のファイルで構成する。

```text
examples/todo/
├── index.html
├── style.css
└── _app.go
```

### 8.1 必須動作

1. inputへTodoの内容を入力できる
2. submit操作でTodoを追加できる
3. 空文字列のTodoを追加しない
4. 追加したTodoを完了状態へ切り替えられる
5. 完了状態をクラスとしてDOMへ反映できる
6. 追加したTodoを削除できる
7. Todo追加後にinputを空にできる
8. すべての操作結果がページ再読込なしで描画へ反映される

Todoの永続化は行わず、ページ遷移または再読込で状態を破棄してよい。

### 8.2 WebGo例

最終的な公開APIの利用イメージを以下とする。

```go
package main

import "growse/dom"

func main() {
    form := dom.GetElementByID("todo-form")
    input := dom.GetElementByID("todo-input")
    list := dom.GetElementByID("todo-list")

    form.OnSubmit(func(event dom.Event) {
        value := input.Value()
        if value == "" {
            return
        }

        item := dom.CreateElement("li")
        item.SetText(value)
        list.AppendChild(item)
        input.SetValue("")
    })
}
```

実装時にAPI名を変更する場合は、本書とサンプルを同時に更新する。

## 9. Runtimeとセキュリティ

### 9.1 実行対象

v0.1.0と同様に、WebGoの自動実行対象は次のローカルホストに制限する。

- `localhost`
- `127.0.0.1`
- `::1`

外部OriginのGoコードを自動実行しない。

### 9.2 Runtimeライフサイクル

以下を保証する。

- ページごとに独立したRuntimeを使用する
- ページ遷移時に以前のRuntimeを停止する
- Reload時に以前のRuntimeを停止して再生成する
- 削除されたDOM要素のハンドラーを呼び出さない
- Runtime Errorをページロードエラーとして扱い、プロセス全体を終了しない

### 9.3 Sandbox

v0.2.0は、信頼できない任意のGoコードを安全に実行できるSandboxを提供しない。

WebGoが利用できるGo標準ライブラリの全面的な制限、プロセス分離、CPU時間制限、およびメモリ制限は将来バージョンの課題とする。

## 11. テスト方針

### 11.1 Unit Test

少なくとも以下をテストする。

- DOM要素の作成、追加、削除
- 循環するDOM操作の拒否
- 属性とクラスの操作
- QuerySelectorの一致と不一致
- inputの値とフォーカス状態
- 各イベントの登録と配信
- 削除済み要素へのイベント非配信
- Mutation通知の回数
- イベントハンドラーのpanic分離

### 11.2 Integration Test

Browser、Runtime、DOM、Style、Layout、およびEventを結合し、以下をテストする。

- WebGoが作成した要素を描画できる
- 動的要素へCSSが適用される
- input操作がWebGoへ配信される
- submitによってDOMが変更される
- Todoの追加、完了、削除が一連で動作する

### 11.3 Regression Test

v0.1.0のCounter Demo、Navigation、History、CSS、Layout、およびYaegi Runtimeのテストを維持する。

## 15. Growse v0.2.0の定義

Growse v0.2.0を以下のように定義する。

> **HTMLとCSSを独自ブラウザエンジンで表示し、GoソースコードからDOMの動的生成、テキスト入力、およびフォームイベントを扱うことで、JavaScriptなしにインタラクティブなWebアプリケーションを構築できるネイティブWebブラウザ。**
