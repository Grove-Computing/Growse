# Growse v0.15.0 スコープ定義書

## 1. 文書概要

本書は、Growse v0.15.0で実装するModern Web Compatibility、すなわちNext.js、SvelteKit、Tailwind CSSで構築された代表的なSSR Pageのframework CSS、resource loading、DOM API、hydration、および描画互換性の範囲、完了条件、対象外を定義する。

v0.15.0は、v0.14.0までのGo / JavaScript Dual Runtime、明示的なTab単位Engine切り替え、外部classic script、ECMAScript Module、WebAssembly、iframe、Service Worker、Runtime worker sandbox、Growse独自DOM / CSS / Layout / Paint、およびDevToolsが完成していることを前提とする。

JavaScript Engineの追加を既存browser engineの埋め込みとは扱わない。Chromium、WebKit、Gecko、WebView、Node.js Runtimeを組み込まず、Growseが所有するHTML、DOM、CSS、Layout、Paint、Network、Runtime lifecycleを拡張する。

---

## 2. リリーステーマ

> **Next.js、SvelteKit、Tailwind CSSで構築されたSSR Pageを、利用者がJavaScript Engineを明示選択したときだけframework CSSとhydrationを壊さず表示・操作できるModern Web Compatibility Releaseへ。**

利用者はSSR済みHTMLを初期表示し、外部stylesheet、Web Font、画像、SVGを反映したPageを確認できる。JavaScript Engineへ明示的に切り替えたTabでは、framework bootstrap、dynamic chunk、Module graph、DOM hydration、Event登録、状態更新を同じDocument、Style、Layout、Paintへ接続し、操作後の見た目を更新できる。

Goは新規Tabの既定Engineとして維持する。Go Engine中はJavaScript classic / Module、dynamic script、modulepreload、およびhydrationを取得・実行せず、Go RuntimeとJavaScript Runtimeの処理、object、callback、errorを共有しない。

## 4. 目標

1. Goを既定Engineとして維持し、JavaScript Engineを明示選択したTabだけでframework script、dynamic resource、hydrationを実行する
2. SSR HTMLへ適用されるmodern CSSのat-rule、selector、cascade、value、typographyを解釈し、frameworkの主要layoutとvisual hierarchyを保持する
3. Next.jsとSvelteKitのclient bootstrapが必要とするDOM、Event、CSSOM、Browser global、observer、dynamic resource APIをGrowse所有modelへ接続する
4. `img`、`picture`、SVG、Web Fontをbounded resourceとして取得・decode・layout・paintし、失敗したresourceだけを隔離する
5. SSR初期表示、hydration完了、利用者操作後、reload、Navigation、Engine切り替えを決定的なfixtureとDevToolsで診断できる
6. v0.14.0のWebGo、Go API、Go Runtime lifecycle、Dual Runtime分離、sandbox、複数Tab、Frame、Service Workerを回帰させない

## 5. 明示的JavaScript EngineとResource lifecycle

### 5.1 Engine境界

新規Tabは既存どおりGo Engineを選択する。通常のHTTP(S) PageにJavaScriptが存在しても、自動的にJavaScript Engineへ切り替えず、Go Engine中はJavaScript classic / Module source、import map、modulepreload、dynamic scriptを取得または評価しない。

利用者がTabの`JS` selectorを操作した場合だけ、完全reload後にJavaScript向けresource分類とRuntimeを有効化する。同じTabでGoへ戻す場合はPage、Frame、Module graph、dynamic resource、observer、Event listener、pending hydration callbackをcancelし、Go Engineで完全reloadする。停止したJavaScript generationのDOM mutationとresource completionをGo Pageへcommitしない。

HTML、stylesheet、image、font、およびGrowseのStyle / Layout / PaintはEngine非依存のBrowser所有基盤とする。CSS互換性の改善はGo Pageにも適用できるが、JavaScript host object、callback、observer、dynamic script実行をGo Runtimeへ公開しない。

### 5.2 Initial resourceとdynamic resource

JavaScript Engineでは、parser-discovered classic / async / defer / Moduleに加え、DOMへ追加された`script`のinline source、`src`、`type="module"`、`async`、`crossorigin`、`integrity`を扱う。接続前に設定された属性をsnapshotし、接続後の規則に従って一度だけprepare、fetch、evaluateし、loadまたはerror Eventを配送する。

`link rel="stylesheet"`、`style`、`link rel="preload" as="style|script|font|image"`、`link rel="modulepreload"`のinitial / dynamic追加と主要attribute変更を扱う。preloadはresource cacheを温めるだけで実行や適用を行わず、後続consumerでOrigin、MIME、CORS、integrityを再検証する。

Module graph、dynamic `import()`、modulepreload、DOM挿入Moduleは正規化URL単位のfetch結果を共有し、同一Moduleを同一Realmで複数回evaluateしない。Navigation、Engine切り替え、Node切断、Page close後はstale completionを破棄する。

### 5.3 Document lifecycle

SSR DocumentはJavaScript Runtime開始前にDOM、stylesheet、font fallback、image placeholderを構築する。hydration scriptは既存Node identityを参照でき、frameworkが置換を要求しない限りBrowser側でSSR treeを作り直さない。

`document.currentScript`、`document.scripts`、`document.styleSheets`、`DOMContentLoaded`、`load`、resource load / errorをresource scheduleと接続する。dynamic resourceがloadを永続的にblockせず、load-blocking対象はPage generationごとに有限集合として管理する。

### 5.4 安全上限

- Pageあたりinitial / dynamic script合計256件、dynamic stylesheet 128件、preload 256件、Module graph 512件までとする
- classic / Module sourceは1件2 MiB、JavaScript source合計32 MiB、CSSは1 Stylesheet 4 MiB・合計16 MiBまでとする
- 同一Nodeのresource再prepare、同一URLの失敗再試行、redirect、dynamic insertion chainへ有限上限を設ける
- resource load / error EventとPromise completionはPage queueで直列化し、pending callback、task時間、IPC sizeにv0.14.0のworker上限を適用する
- JavaScript Engineのresource失敗は対象resourceと依存graphへ閉じ込め、Go Engine、別Tab、Browser processを停止しない

## 6. Hydration向けDOM、CSSOM、Browser API

### 6.1 Interfaceとprototype

JavaScriptへ`EventTarget`、`Node`、`Document`、`DocumentFragment`、`Element`、`HTMLElement`、`HTMLScriptElement`、`HTMLLinkElement`、`HTMLImageElement`、`HTMLTemplateElement`の限定interfaceとprototype chainを提供する。host objectは同一DOM Nodeを同一Realm内で安定したwrapperへ対応付け、`instanceof`、constructor、prototype method呼び出しをfixture範囲で一貫させる。

`document.documentElement`、`head`、`body`、`currentScript`、`scripts`、`styleSheets`、`createDocumentFragment()`、`createElementNS()`、`importNode()`を提供する。Collectionは`length`、index、`item()`、iteratorのsnapshotまたはlive semanticsをinterfaceごとに定義する。

### 6.2 NodeとElement mutation

`nodeType`、`nodeName`、`parentNode`、`parentElement`、`childNodes`、`children`、`firstChild`、`lastChild`、`nextSibling`、`previousSibling`、`isConnected`、`contains()`を提供する。

`appendChild()`、`insertBefore()`、`replaceChild()`、`removeChild()`、`cloneNode()`、`append()`、`prepend()`、`before()`、`after()`、`replaceWith()`、`remove()`、`replaceChildren()`をDocumentFragment展開、cycle拒否、adoption、Node identity、接続状態とともに実装する。

Elementへ`hasAttribute()`、`removeAttribute()`、`toggleAttribute()`、`getAttributeNames()`、`matches()`、`closest()`、`querySelector(All)`、`id`、`className`、`classList`、`dataset`、`style`、`innerHTML`、`outerHTML`、`insertAdjacentHTML()`を提供する。property reflectionはboolean、URL、string、enumerated attributeの本書で使用する型に限定する。

`HTMLTemplateElement.content`は非接続DocumentFragmentとしてparseし、cloneまたは挿入されるまでStyle、Layout、resource executionへ参加させない。`innerHTML`、`outerHTML`、template parseはscript executionをHTML parseとNode接続の規則へ委譲する。

### 6.3 EventとBrowser global

`Event`、`CustomEvent`、`MouseEvent`、`KeyboardEvent`の限定constructorと、`dispatchEvent()`、capture / target / bubble、`once`、`passive`、`stopImmediatePropagation()`を提供する。listener追加・削除・配送はPage queueで直列化し、切断Node、Page close、Engine切り替え後にcallbackを配送しない。

`URL`、`URLSearchParams`、`TextEncoder`、`TextDecoder`、`atob()`、`btoa()`、`performance.now()`、`crypto.getRandomValues()`のBrowser subsetを提供する。OS filesystem、process、environment、raw socket、任意entropy source objectを公開せず、Browserが検証した値だけをworkerへ渡す。

### 6.4 CSSOMとobserver

`CSSStyleDeclaration`として`element.style`のproperty取得、設定、削除、priority、serialized `cssText`を提供し、inline declaration変更をStyle revisionへ接続する。`getComputedStyle()`は同じrevisionのread-only snapshotを返し、Growseが未実装のpropertyを対応済みと偽装しない。

`matchMedia()`と`MediaQueryList`のmatches、change Eventをviewport、color scheme、hover、pointer、reduced motionへ接続する。`getBoundingClientRect()`、`clientWidth` / `clientHeight`、`scrollWidth` / `scrollHeight`は同じLayout revisionを参照する。

`MutationObserver`はattribute、childList、characterData、subtree、oldValueのbounded recordをmicrotask checkpointで配送する。`ResizeObserver`と`IntersectionObserver`はGrowse viewportとLayout Boxに基づく代表的な観測をFrame後に配送し、observer callbackが変更を起こした場合も無限loopを有限errorへ変換する。

### 6.5 安全上限

- PageあたりDOM Node 50,000件、tree深さ256、attributeはNodeあたり256件、文字列は1項目1 MiBまでとする
- Event listener 20,000件、observer合計2,048件、未配送observer record 16,384件、1 checkpoint 1,024 callbackまでとする
- 1 hydration task中のDOM mutation 100,000回、Style / Layout forced read 1,024回を上限とし、超過を対象Pageの有限Runtime errorにする
- structured value、encoded text、random buffer、URL、attribute、dataset、inline styleへ既存IPCとPage payload上限を適用する

## 7. Modern CSS grammar、Cascade、Layout、Paint

### 7.1 At-ruleとCascade Layer

`@layer`のstatement / block、layer順、anonymous layer、nested layer、unlayered ruleとの優先順、および`revert-layer`を実装する。Stylesheet結合、`@import layer()`、inline style、`!important`でlayer順を反転するCascade規則を決定的に扱う。

`@supports`のproperty/value、`selector()`、not / and / orをGrowseの実装能力に基づいて評価する。未実装Featureへtrueを返さず、未知条件内のruleだけを不適用にする。

`@container`のinline-size query、named container、`container-type`、`container-name`を実装し、container size変更後に有限回でStyleとLayoutを安定させる。Style queryとscroll-state queryは対象外とする。

`@font-face`と`@property`をparseし、font resourceと登録Custom Propertyのsyntax、initial value、inheritsを対応範囲へ接続する。未知at-ruleは内側ruleを誤適用せず、DevToolsへ有限な無視理由を記録する。

### 7.2 Selector

`:is()`、`:where()`、複合selector listを持つ`:not()`、`:has()`、`:scope`をSelectors Level 4の対応範囲で実装する。`:is()` / `:where()`のforgiving selector list、`:where()`のゼロ詳細度、`:is()` / `:not()` / `:has()`の詳細度をCascadeへ反映する。

CSS Nestingの`&`、nested selector、nested group ruleを親selectorへ展開し、展開数と深さへ上限を設ける。無効なselectorを含む通常selector listとforgiving selector listの回復規則を区別する。

`:defined`、`:placeholder-shown`、`:read-only` / `:read-write`、`:required` / `:optional`、`:focus-visible`、`:focus-within`を対応するForm、Focus、custom element非対応状態へ接続する。

### 7.3 Value、Color、Logical Property

`min()`、`max()`、`clamp()`とnested `calc()`をLength / Percentageへ実装する。`svw` / `svh`、`lvw` / `lvh`、`dvw` / `dvh`とcontainer query unitをGrowse viewport / containerへ接続する。

CSS Color Level 4からspace区切りrgb / hsl、hex alpha、`hwb()`、`lab()`、`lch()`、`oklab()`、`oklch()`、`color-mix()`のsRGB paintへ変換できる範囲を実装する。非有限値、未知color space、過大計算を無効値として局所化する。

`margin-*`、`padding-*`、`border-*`、`inset-*`、size、min/max sizeのblock / inline logical propertyをhorizontal writing modeへ対応させる。physical / logical declarationのCascade順を保持し、Vertical Writing Mode対応を宣言しない。

### 7.4 Typographyとvisual property

`font-family`、`font-style`、`font-stretch`、`font` shorthand、`text-align`、`text-transform`、`text-indent`、`letter-spacing`、`word-spacing`、`word-break`、`overflow-wrap`、`vertical-align`、`text-overflow`をLayout / Paintへ反映する。

`object-fit`、`object-position`、`list-style`、`appearance`、`accent-color`、`cursor`、`filter`、`backdrop-filter`、`mix-blend-mode`のfixtureで使用するsubsetを実装する。filter、blend、backdropはoffscreen sizeとkernel radiusへ上限を設け、未対応関数だけを無効にする。

### 7.5 安全上限

- Stylesheet合計100,000 rule、1 rule 256 selector、selector複合子64、functional selector深さ32までとする
- Cascade layer 256件、nesting深さ32、展開後selectorは1 rule 1,024件、container query安定化は1 Frame 16 iterationまでとする
- Custom Property 4,096件、1 value 64 KiB、var / calc / color function深さ64までとする
- CSS error、未対応構文、上限超過でStylesheet全体を停止せず、影響するrule、declaration、resourceだけを無効にする

## 8. Image、SVG、Web Font、Replaced Element

### 8.1 Imageとpicture

`img`をintrinsic size、`width` / `height` attribute、CSS size、aspect ratio、object fit / positionを持つreplaced elementとしてLayout / Paintへ接続する。PNG、JPEG、GIFの静止Frame、WebPを扱い、load / error、alt fallback、decode失敗、late size確定後のrelayoutを実装する。

`picture`、`source`、`srcset`、`sizes`をMIME、media query、device scale、viewport widthから選択し、未対応formatを次候補へfallbackする。lazy loadingはviewport近傍の有限policyとし、Page close後のdecode completionを破棄する。

### 8.2 SVG

inline `svg`とHTTP(S)のSVG imageについて、path、rect、circle、ellipse、line、polyline、polygon、text、group、viewBox、fill、stroke、opacity、2D transform、clipPath、linear / radial gradientの静的subsetをrasterizeする。

SVG内script、event handler、external resource、foreignObject、animation、filter、font load、Navigationを実行しない。XML entity、URL参照、node / path command、dimension、raster sizeへ上限を適用し、SVG失敗をplaceholderへ局所化する。

### 8.3 Web Font

`@font-face`のsame-originおよびCORSを通過したcross-origin WOFF / WOFF2 source、family、style、weight、stretch、unicode-range、font-displayの主要値を扱う。redirect、MIME、CORS、mixed content、sizeをdecode前に検証する。

font fallback chainをGrowse同梱Fontへ終端し、Web Font load完了時に影響するTextだけを再計測してLayout / Paint revisionを更新する。decode error、unsupported table、timeout、Page close時はfallback表示を継続する。

### 8.4 安全上限

- imageは1 resource 16 MiB、decode後100 megapixel、1辺16,384 pixel、Page 512件・合計decode surface 256 MiBまでとする
- SVGは1 resource 4 MiB、node 20,000件、path command 200,000件、raster surface 64 MiBまでとする
- Fontは1 resource 8 MiB、Page 64件・合計64 MiB、table 128件・glyph 50,000件までとする
- decoder panic、過大allocation、破損resourceを対象resourceのerrorに変換し、Browserと他Tabを継続する

## 9. Framework fixtureとDevTools診断

### 9.1 Framework fixture

RepositoryへNext.js SSR、SvelteKit SSR、Tailwind CSSの縮約fixture sourceと生成済みHTTP artifactを追加する。fixtureはframework、build tool、依存version、生成command、license、artifact digestをmanifestへ固定し、CI実行時にnpm registry、外部CDN、公開DNS、時刻、credentialを要求しない。

Next.js fixtureはSSR HTML、global CSS / CSS Module、dynamic chunk、hydration、Event、state更新、画像、font、client-side Navigationを含む。SvelteKit fixtureはSSR HTML、scoped style、Module bootstrap、hydration、reactive更新、form enhancement、client-side Navigationを含む。Tailwind fixtureはpreflight、Cascade Layer、Custom Property、responsive / container utility、dark variantを含む。

各fixtureはGo Engineで開いた場合にSSR HTMLとEngine非依存resourceだけを表示し、JavaScript sourceを取得・評価しない。JavaScript Engineで開いた場合はhydration marker、操作結果、DOM identity、Style / Layout revisionを観測できる。

### 9.2 DevTools

DevToolsへScript / Stylesheet / Font / Imageのrequested URL、final URL、resource kind、initiator、schedule、cache、適用状態、有限error categoryを表示する。source body、credential、Cookie、Authorization、Service Worker Cache bodyは保持しない。

Styles診断へ無視したat-rule、selector、declaration、unsupported value、Cascade Layer、media / supports / container条件、font fallback理由を件数上限付きで記録する。Runtime診断へmissing host API、dynamic chunk load、hydration exception、observer loop、stale generationをcontext付きで表示する。

DevTools panelはPage viewportと重ならない独立chrome領域としてlayoutし、通常Pageの上へ重ねてpaintしない。[Issue #78](https://github.com/Grove-Computing/Growse/issues/78)の再現条件をgeometry testとvisual regressionで固定する。

### 9.3 診断上限

- Styles診断はPage 2,000件、resource診断はPage 2,000件、同一原因は集約してcountを保持する
- source body、decoded image、font bytes、DOM mutation payload、observer record内容をDevToolsへ複製しない
- error文字列は1件4 KiBへ切り詰め、URL userinfo、query value、credential、local pathをredactする

## 10. テスト方針

- Unit Test: Engine gate、dynamic resource state machine、DOM interface / prototype、tree mutation、Event、CSSOM、observer、selector、at-rule、Cascade Layer、value、image selection、SVG、font fallback、安全上限を検証する
- Integration Test: local multi-Origin fixture serverを使い、SSR取得、CSS / font / image、dynamic chunk、Module graph、hydration、操作、Navigation、reload、Engine切り替え、CORS、integrity、cancelを検証する
- Framework Test: manifestで固定したNext.js、SvelteKit、Tailwind artifactを配信し、SSR marker、hydration marker、DOM identity、interaction result、resource順、Go / JS分離を検証する
- Visual Regression: 各fixtureのSSR初期状態、hydration後、操作後、responsive、font fallback、image error、DevTools open状態を固定Viewport、Font、Scale、clockで比較する
- Conformance Test: WPTからDOM、HTML dynamic script / link、Selectors、Cascade Layer、CSSOM、observer、image、fontに対応するcaseを選定し、縮約内容と未対応理由を記録する
- Security Test: resource bomb、malformed CSS / SVG / font / image、observer loop、mutation storm、dynamic insertion chain、stale generation、credential redactionを検証する
- Regression Test: Go EngineでJavaScript request、Module fetch、hydration callback、JavaScript errorが発生せず、既存WebGo ShowcaseのDOM / Event / CSS / Fetchが同じ結果になることを検証する

公開WebサイトをCIの合否条件に使用しない。手動確認はcredential不要の公開Pageに限定し、Release判定はRepository内のoffline fixtureと選定WPTだけで再現できるものとする。
