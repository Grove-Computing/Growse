# Growse v0.20.0 スコープ定義書

## 1. 文書概要

本書は、Growse v0.20.0 で実装する **Real-World CSS Compatibility** の範囲、完了条件、対象外を定義する。本書を v0.20.0 の唯一の進捗台帳とし、実装、test、visual evidence、文書、CI が揃うまで完了 checkbox を更新しない。

v0.19.0 までの CSS Layout、resource loading、JavaScript Runtime と、v0.20.0 の初期開発で追加した text / paint の fixture は実装基盤として利用する。ただし、localhost の Showcase と局所 fixture が成功しても、実サイトで本文が消失し、文字が切れ、要素が重なる状態は Release 完了とみなさない。

### 1.1 再定義理由

2026-09-19 の実サイト確認で、少なくとも次の Release blocker を確認した。

- GitHub profile で主要本文が消失し、navigation の一部だけが残る
- 日本語 Wikipedia で本文・見出し・画像を含む page の大部分が欠落する
- 1MB Club で navigation label、section heading、table 周辺が切れ、配置が崩れる
- KIDLAT で長い heading と本文が重なり、line box と実 glyph の高さが一致しない
- 単純な文書では描画できても、複雑な cascade、intrinsic sizing、flow、runtime 更新が加わると同じ品質を維持できない

このため、従来の「Typography & CSS Visual Fidelity」の完了判定と desktop gate 記録を撤回する。#150〜#156 の成果は削除せず、以後の実サイト修正を支える基盤として扱う。閉じた `release/v0.20.0` → `main` PR #157 は Release 承認の証跡に含めない。

2026-09-20 のPR #168マージ後確認では、`1mb.club` のsection heading下端とbadge行上端で実glyphがline boxに切られる問題が残っていた。構造boundsだけのgateでは検出できなかったため、PR #168の完了判定を撤回し、実rasterのink boundsとCSS baselineを追加のRelease blockerとして扱う。

---

## 2. リリーステーマ

> **代表的な実サイトで、主要内容が消えず、文字が切れず、CSS layout が読める形を保つ browser rendering baseline を確立する。**

利用者は、単純な static page だけでなく、navigation、table、画像、Web Font、CJK、Flexbox、Grid、position、overflow、JavaScript 更新を含む page を読める。開発者は、再現可能な real-site fixture、参照 browser screenshot、Growse screenshot、region 差分、computed style / layout diagnostic を使って破綻の原因を特定できる。

「CSS が完全」という主観的な表現は合否条件にしない。本 Release では、6章の固定 corpus に対して P0 / P1 がゼロであり、P2 が明示した許容差内にあることを合格条件とする。

## 3. 準拠基準

- CSS 2.1 Visual Formatting Model、CSS Display、CSS Sizing、CSS Box Model、CSS Overflow の選定範囲
- CSS Cascade、CSS Values、CSS Variables、Media Queries、Conditional Rules の選定範囲
- CSS Text、CSS Inline Layout、CSS Fonts、CSS Writing Modes の選定範囲
- CSS Flexbox、CSS Grid、CSS Tables の選定範囲
- CSS Position、CSS Transforms、CSS Backgrounds and Borders、CSS Color、Compositing の選定範囲
- 各修正に対応する WPT 由来 assertion と、固定 Chromium reference screenshot

仕様全体、任意の Web site、任意の browser / OS / font との pixel 完全一致は宣言しない。本書に列挙した corpus、観測項目、重大度、許容差に限定する。

## 4. 目標

1. 実サイト corpus の主要内容を欠落させる style、layout、paint、runtime 更新の原因を修正する
2. cascade から paint までの各段階を同じ fixture で追跡し、症状ではなく互換性 gap を回帰 test にする
3. block / inline flow、intrinsic sizing、Flexbox、Grid、Table、position、overflow の組合せで、文字切れ・重なり・意図しない省略を防ぐ
4. CJK / Latin / 記号、fallback font、Web Font、長い heading で line box、baseline、wrap と raster glyph を一致させる
5. desktop / narrow viewport、reload、scroll、focus、link、image / font 完了、局所的な script error を含む Release gate を決定的に検証する

## 5. Real-Site Evidence Foundation

### 5.1 固定 corpus と参照情報

CI は network に依存せず、取得日、source URL、content hash、viewport、DPR、locale、font set、参照 browser version、resource manifest を記録した sanitized fixture を使う。認証情報、cookie、個人化 response、tracking payload、不要な大容量 asset は保存しない。live site の変更は自動で baseline に反映せず、fixture 更新 PR で provenance と差分を review する。

各 case は次を生成する。

- Growse screenshot、固定 Chromium reference、差分画像
- main content、navigation、heading、text、table / list、image の semantic region metric
- DOM node count、displayed element count、stylesheet / font / image の load 状態
- cascade source、computed style、containing block、used size、line box、clip chain の診断

### 5.2 観測の安全上限

- 一画像は最大 16 megapixel、単一 artifact は最大 16 MiB、全 corpus artifact は最大 256 MiB
- 一 page は最大 50,000 glyph、4,000 displayed element、256 stylesheet、8,192 CSS rule を診断対象とする
- 上限超過は panic、hang、無言の省略にせず、page と limit を示す有限な失敗にする
- screenshot 差分は anti-aliasing の微差と、geometry / visibility / clipping の構造差を分離する

## 6. 必須 Real-Site Corpus

次の page を desktop と narrow viewport で固定する。live URL は Release candidate での smoke check に使い、CI では同一条件の captured fixture を使う。

| Case | URL / 種別 | 主な受入観測 |
| --- | --- | --- |
| complex directory | `https://1mb.club/` | navigation が読める、section heading が切れない、説明と table row / column が重ならない |
| CJK encyclopedia | `https://ja.wikipedia.org/` の代表 main-page fixture | logo、navigation、主要 heading、本文、画像領域が欠落せず、CJK line が重ならない |
| runtime-heavy profile | `https://github.com/Saku0512` | server-rendered navigation / profile 本文が残り、unsupported script の失敗が page 全体を消さない |
| minimal control A | `https://cv.btxx.org/` | UA default、`pre` / plain text、link、改行を維持する |
| minimal control B | `https://t0.vc/` | plain flow、link、section 間隔を維持する |
| semantic list | `https://www.schemescape.com/` | heading、emoji、list、link、本文の baseline と間隔を維持する |
| editorial layout | `https://kidlat.at/` | Web Font / fallback、長い heading、category、本文が重ならず、viewport 内で適切に wrap する |

simple control の成功だけで Release を合格にしない。全 case が同じ gate を通過する必要がある。

### 6.1 重大度

- **P0 — content loss:** main content が空、主要 section が消失、page の大半が非表示、render が停止する
- **P1 — structural breakage:** 読解を妨げる文字切れ・重なり、navigation / table / heading の重大な崩れ、誤った clip / overflow、操作後の主要内容消失
- **P2 — bounded visual difference:** 読解や操作を妨げない spacing、色、anti-aliasing、1 CSS px 程度の局所差

Release 条件は corpus 全体で P0 = 0、P1 = 0 とする。P2 は region ごとの許容差を fixture に記録し、未説明の baseline 更新は禁止する。

## 7. Cascade and Style Resolution

UA stylesheet、author stylesheet、inline style、inheritance、initial / unset / revert、specificity、source order、`!important`、cascade layer を一貫して解決する。shorthand / longhand、custom property、`var()` fallback、`calc()`、logical property、pseudo-class / pseudo-element、generated content が computed style から脱落しないことを確認する。

`@import`、`@media`、`@supports`、font-face と stylesheet load の成功・失敗・順序を固定する。未知の selector / declaration / at-rule は規定の単位で無効化し、stylesheet 全体や兄弟要素の style を消失させない。

---

## 8. Flow and Intrinsic Sizing

block / inline formatting、anonymous box、margin collapse、float / clear、BFC、containing block、replaced element を実サイト構造で検証する。`auto`、percentage、min / max width・height、min-content、max-content、fit-content、shrink-to-fit、aspect-ratio、box-sizing の used value を有限かつ再現可能にする。

layout が計算した content / border box、line box、scroll overflow と paint / hit-test が同じ geometry を使う。省略指定がない text に暗黙の ellipsis を適用せず、`overflow: visible` の glyph や decoration を親 content box で切らない。

---

## 9. Flexbox, Grid, and Table

Flexbox の automatic minimum size、flex base size、free-space distribution、wrap、baseline alignment、percentage sizing を検証する。Grid の intrinsic track sizing、`fr`、`minmax()`、spanning item、auto placement、gap、subgrid 対応範囲を回帰させる。

Table は table / row group / row / cell の anonymous wrapper、column width、span、caption、border model、cell baseline を扱う。column が viewport 外へ不必要に押し出されず、header と data の対応が読めることを corpus の region assertion にする。

---

## 10. Positioning, Overflow, and Paint

relative / absolute / fixed / sticky の containing block、inset、stacking context、z-order を一致させる。root / nested scroll container の scrollport、overflow visible / hidden / clip / auto、rounded clip、transform clip、viewport resize 後の geometry を検証する。

background、border、radius、shadow、opacity、image、gradient、2D transform を、内容を消さない局所 fallback と共に描画する。遅延 image / font / stylesheet 完了後は新しい generation だけを commit し、古い clip、layout、raster cache を復活させない。

---

## 11. Typography and Runtime-Visible Content

Latin、CJK、数字、句読点、emoji / symbol、combining mark の font fallback、glyph advance、ascent / descent、baseline、line-height、wrap を同じ shaped run から layout / paint する。長い heading、mixed font、bold、link、`pre`、vertical-align、white-space、word-break、overflow-wrap を corpus と局所 fixture の両方で固定する。

JavaScript / custom element / hydration の全互換性は本 Release の対象外だが、unsupported script の例外で既に存在する server-rendered / static content を page 全体から消してはならない。script failure は局所化し、status / DevTools に原因を残し、navigation、profile、fallback content を読める状態に保つ。

---

## 12. テスト方針

- Unit Test: cascade、used value、intrinsic sizing、line box、containing block、clip chain の最小再現を固定する
- Integration Test: captured document、stylesheet、font、image、script failure を resource pipeline から raster commit まで通す
- Visual Regression: desktop / narrow の Chromium reference と region 単位で比較し、P0 / P1 を構造 assertion でも検出する
- Conformance Test: 修正対象の CSS / HTML semantics に対応する WPT 由来 assertion と出典を追加する
- Live Smoke: Release candidate HEAD で corpus URL を手動取得し、fixture との差異と外部変更を分離して記録する

pixel diff の小ささだけを合格条件にしない。主要 region の存在、可視 text、非重複、clip、scroll 到達性を数値と screenshot の両方で検証する。

## 13. 実装フェーズ

### Phase 1 — Real-Site Evidence Foundation

captured corpus、reference metadata、semantic region assertion、P0 / P1 classifier、diagnostic artifact を導入する。

### Phase 2 — Cascade, Flow, and Intrinsic Sizing

Wikipedia、1MB Club、minimal controls を起点に style resolution、block / inline flow、intrinsic sizing、Table を修正する。

### Phase 3 — Flex, Grid, Position, and Overflow

複雑な navigation / editorial layout を起点に automatic minimum size、track sizing、containing block、scroll / clip を修正する。

### Phase 4 — Typography and Runtime Resilience

KIDLAT、Wikipedia、GitHub を起点に line metrics、font fallback、長文 wrap、SSR content preservation、script failure isolation を修正する。

### Phase 5 — Release Quality

全 corpus の desktop / narrow visual gate、live smoke、performance / safety、documentation、cross-platform packaging、必須 CI を完了する。

### Phase 6 — Text Ink Bounds and Baseline Correction

1MB Clubの見切れを起点に、layoutが決めたCSS baselineをUI backendの実glyph描画へ反映し、ink boundsを検査するraster gateと再live smokeを完了する。
