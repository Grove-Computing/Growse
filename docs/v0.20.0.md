# Growse v0.20.0 スコープ定義書

## 1. 文書概要

本書は、Growse v0.20.0 で実装する **Typography & CSS Visual Fidelity** の範囲、完了条件、対象外を定義する。

v0.20.0 は、v0.19.0 までの CSS Layout 2026 Baseline、実サイト fixture、Browser-grade resource loading、Go / JavaScript Runtime を前提とする。v0.19.0 で layout algorithm と安全上限を広げた一方、実際の画面ではテキストの glyph fallback、baseline、line box、折返しと CSS の装飾・clip・transform の組合せに差分が残る。本 Release は「構文を受理する」だけでなく、実際に raster 化した画面を観測して差分を修正する。

リリース開始時点で `release/v0.20.0` に取り込まれている #147 と #142 は、本 Release のネットワーク・ローカル開発基盤として扱う。

---

## 2. リリーステーマ

> **文字を正しく組み、CSS の見た目を実スクリーンショットで検証して、通常の Web Page を「読めて、崩れず、意図どおりに見える」ブラウザへ。**

利用者は Latin、CJK、記号が混在する通常のページを、欠落 glyph、行の重なり、誤った折返し、装飾の clip なしに読める。開発者は固定 viewport・font・scale・clock で生成した Growse の raster screenshot と Chromium 参照を比較し、テキストまたは CSS の視覚差分を再現可能な fixture、数値、画像で修正できる。

---

## 3. 準拠基準

- CSS Text Level 3、CSS Inline Layout Level 3、CSS Fonts Level 4 の、font selection、fallback、line-height、white-space、word-break、overflow-wrap、text-decoration、text-shadow の選定範囲
- CSS Writing Modes Level 3 の horizontal-tb、vertical-rl、vertical-lr と glyph orientation の安全な subset
- CSS Backgrounds and Borders Level 3、CSS Color Level 4、CSS Transforms Level 1、Compositing and Blending Level 1、Filter Effects Level 1 の選定範囲
- CSS 2.1 Visual Formatting Model と、各仕様節に対応する選定 WPT assertion
- 固定した Chromium reference screenshot と、offline Next.js / SvelteKit / Tailwind fixture

仕様全体、任意サイト、全 font、全ブラウザとの pixel 完全一致は宣言しない。本書で列挙する property、fixture、reference、許容差に限定する。

---

## 4. 目標

1. Layout が計測した glyph advance、baseline、line box と Paint が raster 化する文字を同じ shaping 結果から生成する
2. bundled font、Web Font、system font fallback の CJK / Latin / 記号混在で、欠落 glyph、非有限 geometry、fallback ループを発生させない
3. background、border、radius、shadow、text decoration、transform、clip、opacity、filter の高頻度な組合せを、通常の CSS Page で視覚的に破綻させない
4. 実際の raster screenshot を生成・保存・比較する deterministic visual test を導入し、白紙 artifact や display-list だけの検証を完了条件にしない
5. CSS Layout 2026、Modern Web Compatibility、Visual Fidelity Showcase と固定 framework corpus を desktop / narrow viewport で確認する
6. proxy 切替とローカル開発 port を安定した Release 基盤として維持する

---

## 5. リリース基盤と観測可能な Visual Evidence

### 5.1 既存基盤

HTTP client は request ごとに `HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY` を再評価し、動作中の proxy 切替後も新しい request が古い proxy 設定を保持しない。Browser UI と同梱 Showcase の既定ローカル URL は `http://localhost:6053` とし、Showcase の `-addr` 指定で任意 port を維持する。

### 5.2 Screenshot Harness

Visual test は、HTML / CSS fixture、viewport、DPR、font collection、locale、clock、resource response を固定し、Display List を実際に raster 化した PNG を生成する。各 case は少なくとも次を保存または assertion として出力する。

- Growse screenshot、参照 screenshot、差分画像または pixel / region metric
- viewport、DPR、font fallback chain、CSS / layout revision、resource state
- text run の glyph count、advance、baseline、line box と、差分が閾値を超えた region

baseline 更新は期待 fixture の変更または参照ブラウザ更新を伴う review 対象とし、差分を無条件に上書きしない。既存の `text_render_verify_test.go` のように空の bitmap を出すだけの artifact は visual evidence とみなさない。

### 5.3 差分の扱いと安全上限

fixture ごとに text region と non-text region を分け、anti-aliasing による小さな差と layout / clipping の構造差を区別する。比較画像、差分画像、single test artifact は一件あたり 16 MiB、全 visual corpus は 256 MiB、比較対象 pixel は一画像 16 megapixel、glyph / run diagnostic は一 page あたり 50,000 glyph を上限とする。上限超過は panic や無限比較ではなく、明示的な diagnostic で test を失敗させる。

---

## 6. Text Rendering Reliability

### 6.1 Shaping、計測、Paint の一致

Inline Layout は text run ごとに選択した face、glyph advance、offset、baseline、letter spacing、word spacing を保持する。Paint はこの結果を再計測せず、同じ run を raster backend へ渡す。fallback font に切り替わる run、Web Font の完了、font style / weight / stretch、text shadow、decoration が line box と異なる geometry を生まないことを確認する。

既定の比率による baseline 補完は、font metric が利用できる場合の最終値として使わない。metric が取得不能な font では有限な fallback を使い、診断可能にする。

### 6.2 文字集合と改行

bundled font、JS Page の system fallback、WOFF / WOFF2 Web Font に対して、Latin、CJK、数字、句読点、記号、combining mark の混在を検証する。`white-space`、`word-break`、`overflow-wrap`、`text-indent`、`text-overflow`、複数 inline / atomic inline、line-height、vertical-align を selected fixture に含める。Unicode bidi algorithm 全体、hyphenation dictionary、complex script の shaping 完全性は対象外だが、未対応入力は glyph 欠落・重なり・panic にしない。

### 6.3 Vertical Writing

horizontal-tb、vertical-rl、vertical-lr の CJK / Latin 混在を screenshot と geometry assertion で検証する。縦書きで baseline、clip、selection / hit-test geometry、inline replaced element が破綻しないことを確認する。Ruby、縦中横、sideways 値、text-orientation 全値は対象外とする。

---

## 7. CSS Visual Fidelity

### 7.1 Surface、Border、Typography Decoration

background color / image の layer、linear / radial gradient、position / size / repeat、border style / width / radius、outline、box shadow、text shadow、text decoration を同じ clip / stacking context で描画する。nested radius、overflow、opacity、background clip、複数 shadow、inline decoration を selected fixture と screenshot で検証する。

未対応の paint function は宣言全体を壊さず局所 fallback とし、対応済みの背景や text を消失させない。3D transform、SVG filter 全体、任意 shader、全 blend mode は対象外である。

### 7.2 Transform、Clip、Opacity、Filter

2D translate / scale / rotate / skew / matrix、transform origin、nested transform、rounded clip、overflow clip、group opacity、選定 filter と hit testing の geometry を一致させる。raster cache は transform / filter / target size / DPR / style revision を識別し、古い page generation や image completion を新しい screenshot へ混入させない。

### 7.3 Style Resolution と実サイト CSS

Tailwind utility、cascade layer、custom property、`calc()`、logical property、pseudo class の既存対応を、視覚 fixture で回帰させる。property を parser が受理しても computed style、Layout、Paint のいずれかで効果が失われる場合は、同一 fixture の screenshot と computed / display-list diagnostic から原因を分離する。

---

## 8. Framework Corpus、Showcase、実機確認

`examples/modern-web-compat` の Next.js / SvelteKit / Tailwind fixture、`examples/css-layout-2026`、新設する Visual Fidelity Showcase を対象にする。Visual Fidelity Showcase は一画面で次を切り替えまたは観測できる。

- Latin / CJK / 記号 / fallback font、line-height、wrap、ellipsis、text shadow / decoration
- horizontal / vertical writing、inline / atomic inline / replaced element の baseline
- gradient、radius、border、box shadow、text shadow、nested clip、opacity
- nested 2D transform、filter、scroll、hover / focus、viewport resize、Web Font / image completion
- Growse screenshot と expectation region の status、font chain、visual diff diagnostic

CI は network を使わない固定 resource と reference だけを使用する。Release PR と最終 Release HEAD では、desktop app を実際に起動して screenshot を取得し、Showcase、framework fixture、代表的な通常 page を desktop / narrow viewport で確認する。

## 9. 実装フェーズ

### Phase 1 — Visual Evidence Foundation

実 raster screenshot harness、reference / diff artifact、region metric、font / layout diagnostic を導入し、既存の白紙 artifact を置き換える。

### Phase 2 — Text Shaping and Line Reliability

run ownership、font fallback、font metric、baseline、line box、wrapping、decoration、vertical writing を修正し、Latin / CJK fixture で固定する。

### Phase 3 — CSS Surface and Compositing Fidelity

background、border、radius、shadow、decoration、clip、opacity、2D transform、filter と raster cache の視覚差分を修正する。

### Phase 4 — Framework and Desktop Quality

Tailwind / Next.js / SvelteKit、CSS Layout Showcase、Visual Fidelity Showcase の desktop / narrow screenshot、resize、scroll、resource completion を検証する。

### Phase 5 — Release Quality

WPT 由来 assertion、performance / safety gate、documentation、各 OS packaging、CI、最終 desktop visual gate を完了する。

---

## 10. v0.20.0 非対象

- Chromium、Firefox、WebKit、WebView の埋め込みまたは描画委譲
- 任意 Web site、全 CSS 仕様、全 WPT、全 OS / font の pixel 完全一致
- 完全な Unicode bidi / line breaking / hyphenation、complex script shaping の完全実装
- Ruby、縦中横、text-orientation 全値、MathML、SVG text layout 全体
- 3D transform、perspective、WebGL / WebGPU、SVG filter 全体、任意 blend / shader effect
- Print / Paged Media、native control の platform pixel parity、Android / iOS 対応
- GrowseKit の実装（本 repository に含まれない）
- annotated tag の push または GitHub Release の公開

## 12. Growse v0.20.0 の定義

Growse v0.20.0 とは、固定された実 raster screenshot と選定 reference によって、通常の Latin / CJK Web Page の text、line、surface、clip、transform、opacity、selected filter が観測可能に検証され、layout・paint・hit testing・resource completion の差分を再現可能な fixture で修正できる Release である。
